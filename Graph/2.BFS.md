# 1. What is BFS?

## Definition

**Breadth First Search (BFS)** is a graph traversal algorithm that explores all the neighboring vertices of a node **before moving to the next level**.

It visits nodes **level by level**.

> **Interview Definition**
> 
> "Breadth First Search (BFS) is a level-order graph traversal algorithm that uses a Queue (FIFO) to visit all reachable vertices, ensuring that all immediate neighbors are processed before moving deeper into the graph."

---

# Example Graph

```
        A
      /   \
     B     C
    / \   / \
   D   E F   G
```

### BFS Traversal

```
A → B → C → D → E → F → G
```

Notice:

- Visit A
- Visit all neighbors of A (B, C)
- Visit all neighbors of B and C
- Continue level by level

---

# 2. Why is it Called Breadth First Search?

Because it explores the graph **breadth-wise (level by level)** instead of depth-wise.

```
Level 0 : A

Level 1 : B C

Level 2 : D E F G
```

It finishes one level completely before moving to the next.

### Most Common Applications

- Shortest Path in Unweighted Graph ⭐⭐⭐⭐⭐

# 4. Why Do We Use a Queue?

Queue follows **FIFO (First In, First Out)**.

The first discovered node should be processed first.

Example:

```
Queue

Front → A
```

Process A

Add neighbors

```
Front → B → C
```

Process B

```
Front → C → D → E
```

Process C

```
Front → D → E → F → G
```

Queue naturally maintains **level order**.

---

# 5. BFS Algorithm

### Steps

1. Start from the source node.
2. Mark it as visited.
3. Insert it into the queue.
4. Repeat until the queue becomes empty:
    - Remove the front node.
    - Process it.
    - Visit all unvisited neighbors.
    - Mark them visited.
    - Add them to the queue.

# Java Code (Most Asked)

```
import java.util.*;

public class BFSGraph {

    public static void bfs(int start, List<List<Integer>> graph) {

        // Keeps track of visited vertices
        boolean[] visited = new boolean[graph.size()];

        // Queue for BFS
        Queue<Integer> queue = new LinkedList<>();

        // Mark source as visited
        visited[start] = true;

        // Add source to queue
        queue.offer(start);

        while (!queue.isEmpty()) {

            // Remove front vertex
            int current = queue.poll();

            // Process current vertex
            System.out.print(current + " ");

            // Visit all neighbours
            for (int neighbour : graph.get(current)) {

                if (!visited[neighbour]) {

                    visited[neighbour] = true;

                    queue.offer(neighbour);
                }
            }
        }
    }

    public static void main(String[] args) {

        int V = 6;

        List<List<Integer>> graph = new ArrayList<>();

        for (int i = 0; i < V; i++)
            graph.add(new ArrayList<>());

        graph.get(0).add(1);
        graph.get(0).add(2);

        graph.get(1).add(0);
        graph.get(1).add(3);
        graph.get(1).add(4);

        graph.get(2).add(0);
        graph.get(2).add(5);

        graph.get(3).add(1);
        graph.get(4).add(1);
        graph.get(5).add(2);

        bfs(0, graph);
    }
}
```

Output

```
0 1 2 3 4 5
```

# Why Mark Visited Before Adding to Queue? ⭐⭐⭐⭐⭐

Correct

```
visited[neighbour] = true;
queue.offer(neighbour);
```

### Why?

This prevents the same vertex from being inserted into the queue multiple times.

Wrong

```
queue.offer(neighbour);
visited[neighbour] = true;
```

Two different parents may enqueue the same vertex before it is marked visited, causing duplicate processing.

---

# Time Complexity

Each vertex is visited once:

```
O(V)
```

Each edge is examined once (directed) or twice (undirected):

```
O(E)
```

Overall

```
O(V + E)
```

---

# Space Complexity

Visited array

```
O(V)
```

Queue

```
O(V)
```

Total

```
O(V)
```

# BFS vs DFS

|BFS|DFS|
|---|---|
|Queue|Stack / Recursion|
|Level-wise traversal|Goes deep first|
|Finds shortest path in unweighted graph|Does not guarantee shortest path|
|More memory in wide graphs|Usually less memory in wide graphs|
|Good for shortest path|Good for backtracking and connectivity|

# Common Mistakes

### ❌ Forgetting the visited array

May cause infinite loops in cyclic graphs.

---

### ❌ Marking visited after polling

Can enqueue the same node multiple times.

Correct:

```
visited[neighbour] = true;
queue.offer(neighbour);
```

---

### ❌ Using `add()` instead of `offer()`

`offer()` is preferred because it returns `false` if insertion fails, whereas `add()` throws an exception.

---

### ❌ Using `remove()` instead of `poll()`

`poll()` returns `null` if the queue is empty, while `remove()` throws an exception.

# Frequently Asked Interview Questions ⭐⭐⭐⭐⭐

### 1. Why does BFS use a Queue?

Because BFS processes vertices in the order they are discovered (FIFO), which naturally produces level-order traversal.

---

### 2. Why do we mark a node as visited before adding it to the queue?

To avoid inserting the same node multiple times when it is reachable from different parents.

---

### 3. What is the time complexity of BFS?

**O(V + E)**, where `V` is the number of vertices and `E` is the number of edges.

---

### 4. Can BFS be implemented using recursion?

Not naturally. BFS relies on a queue to maintain level order. While recursion can simulate a queue, it is inefficient and uncommon; recursion is better suited to DFS.

---

### 5. When is BFS preferred over DFS?

- Shortest path in an unweighted graph.
- Level-order traversal.
- Problems requiring minimum number of steps or edges.

---

### 6. What happens if the graph contains a cycle?

Without a `visited` array, BFS may revisit nodes indefinitely. The `visited` array ensures each vertex is processed only once.

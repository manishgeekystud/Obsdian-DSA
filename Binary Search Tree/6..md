# 1. Problem Statement

Given a **Binary Search Tree (BST)** where **exactly two nodes have been swapped by mistake**, restore the BST **without changing its structure**.

> **Goal:** Swap back the values of the incorrect nodes.

# 3. Core Observation (Interview Key)

### Property of BST

**Inorder Traversal of a BST is always sorted in ascending order.**

Example:

```
      4
     / \
    2   6
   / \ / \
  1  3 5  7

Inorder:

1 2 3 4 5 6 7
```

---

Now suppose 3 and 6 are swapped.

```
      4
     / \
    2   3
   / \ / \
  1  6 5  7
```

Inorder becomes

```
1 2 6 4 5 3 7
```

Notice

```
6 > 4

5 > 3
```

These are called **violations**.

---

# 4. Intuition ⭐⭐⭐⭐⭐

Never memorize the code.

Remember this idea:

> **A BST should produce a sorted inorder traversal. If two nodes are swapped, the sorted order breaks at one or two places. Detect those broken places and swap the wrong nodes back.**

Think of it like:

```
Sorted Array

1 2 3 4 5 6 7
```

Swapped

```
1 2 6 4 5 3 7
```

Find

```
6 > 4

5 > 3
```

Swap

```
6

and

3
```

Everything becomes sorted again.

# 5. Brute Force Solution

### Idea

- Store inorder traversal in ArrayList.
- Sort it.
- Compare original inorder with sorted inorder.
- Find mismatched nodes.
- Traverse tree again and replace values.

### Complexity

Time

```
O(N log N)
```

Space

```
O(N)
```

# Why Not Optimal?

- Extra array
- Sorting required
- Additional traversal

# 6. Optimal Solution ⭐⭐⭐⭐⭐

### Key Idea

During inorder traversal,

Keep previous node.

If

```
previous.data > current.data
```

BST property is violated.

Record nodes.

Finally swap their values.

# 12. Java Code (Commented)

```
class Solution {

    Node first, middle, last, previous;

    void inorder(Node root) {

        if (root == null)
            return;

        inorder(root.left);

        // Check BST violation
        if (previous != null && previous.data > root.data) {

            // First violation
            if (first == null) {
                first = previous;
                middle = root;
            }
            // Second violation
            else {
                last = root;
            }
        }

        // Update previous node
        previous = root;

        inorder(root.right);
    }

    public void recoverTree(Node root) {

        inorder(root);

        // Non-adjacent swap
        if (last != null) {

            int temp = first.data;
            first.data = last.data;
            last.data = temp;
        }
        // Adjacent swap
        else {

            int temp = first.data;
            first.data = middle.data;
            middle.data = temp;
        }
    }
}
```

# 17. Interview Follow-up Questions ⭐⭐⭐⭐⭐

### Q1. Why does inorder traversal help here?

**Answer:** Because the inorder traversal of a BST is always sorted. Any violation in this order indicates misplaced nodes.

---

### Q2. Why can there be one or two violations?

- **Adjacent swapped nodes:** One inversion.
- **Non-adjacent swapped nodes:** Two inversions.

---

### Q3. Why don't we swap immediately after the first violation?

Because in the non-adjacent case, the second incorrect node hasn't been discovered yet. Swapping too early would produce the wrong result.

---

### Q4. Can this be solved iteratively?

**Yes.** Use an explicit stack to perform inorder traversal and apply the same `previous`, `first`, `middle`, and `last` logic.

---

### Q5. Can it be solved in O(1) extra space?

**Yes.** By using **Morris Inorder Traversal**, which temporarily modifies tree links to avoid recursion or an explicit stack. This achieves **O(N)** time and **O(1)** extra space.

---

### Q6. Why do we swap values instead of changing pointers?

Changing pointers can alter the tree structure and requires updating parent-child relationships. Swapping values restores the BST while preserving the original structure.

---

> **Recover BST = Inorder should be sorted → Find inversion(s) using `previous` → Record `first`, `middle`, `last` → Swap `first` with `last` (or `middle` if only one inversion).**

# What is Vertical Traversal?

Vertical Traversal means printing nodes **column by column** from **leftmost vertical line to rightmost vertical line**.

Every node is assigned a **Horizontal Distance (HD)** from the root.

```
Root HD = 0

Left Child  = Parent HD - 1
Right Child = Parent HD + 1
```

Example

```
        1
      /   \
     2     3
    / \   / \
   4  5  6   7
```

Horizontal Distance

```
           1(0)

      2(-1)     3(+1)

 4(-2) 5(0) 6(0) 7(+2)
```

Now group by HD

```
HD -2 : 4

HD -1 : 2

HD  0 : 1 5 6

HD +1 : 3

HD +2 : 7
```

Output

```
[[4],[2],[1,5,6],[3],[7]]
```

---

# How do we calculate Horizontal Distance?

Rule:

```
Root = 0

Go Left  -> HD - 1

Go Right -> HD + 1
```

Example

```
        10
       /  \
     20    30
    /
  40
```

```
10 -> HD 0

20 -> -1

30 -> +1

40 -> -2
```

---

# Why can't we use DFS directly?

Suppose

```
          1
         / \
        2   3
         \
          4
           \
            5
```

DFS order

```
1 2 4 5 3
```

Vertical order should be

```
HD -1 : 2

HD 0 : 1 4

HD +1 : 3 5
```

DFS may visit deeper nodes before shallower ones.

Interviewers generally expect **Level Order (BFS)** because it naturally preserves top-to-bottom ordering.

---

# Best Approach (BFS + TreeMap)

Use

```
Queue<Pair<Node, HD>>

TreeMap<Integer, List<Integer>>
```

Why TreeMap?

Because keys stay sorted automatically.

```
-2
-1
 0
 1
 2
```
The **TreeMap key stores the Horizontal Distance (HD)** of each node from the root.

Think of it like this:

```
TreeMap<HorizontalDistance, List of Nodes>
```
---

# Algorithm

### Step 1

Store root with HD = 0

```
Queue

(1,0)
```

---

### Step 2

While queue not empty

Remove front node.

```
(node, hd)
```

Insert

```
map.get(hd).add(node.data)
```

---

### Step 3

If left child exists

```
HD - 1
```

Push into queue.

---

### Step 4

If right child exists

```
HD + 1
```

Push into queue.

---

### Step 5

At the end

TreeMap contains vertical order.

---

# Java Code (BFS)

```java
import java.util.*;

class Pair {
    Node node;
    int hd;

    Pair(Node node, int hd) {
        this.node = node;
        this.hd = hd;
    }
}

class Solution {

    static ArrayList<ArrayList<Integer>> verticalOrder(Node root) {

        ArrayList<ArrayList<Integer>> result = new ArrayList<>();

        if (root == null)
            return result;

        // HD -> List of nodes
        TreeMap<Integer, ArrayList<Integer>> map = new TreeMap<>();

        Queue<Pair> queue = new LinkedList<>();

        queue.offer(new Pair(root, 0));

        while (!queue.isEmpty()) {

            Pair current = queue.poll();

            Node node = current.node;
            int hd = current.hd;

            // Create list if HD not present
            map.putIfAbsent(hd, new ArrayList<>());

            // Store current node
            map.get(hd).add(node.data);

            // Left child
            if (node.left != null)
                queue.offer(new Pair(node.left, hd - 1));

            // Right child
            if (node.right != null)
                queue.offer(new Pair(node.right, hd + 1));
        }

        // Convert TreeMap values into result
        for (ArrayList<Integer> list : map.values()) {
            result.add(list);
        }

        return result;
    }
}
```

# Frequently Asked Follow-up Questions

### 1. Why use TreeMap?

Because it keeps horizontal distances sorted automatically.

```
-2

-1

0

1

2
```

---

### 2. Why use Queue instead of Stack?

Queue performs **Level Order Traversal (BFS)**, preserving **top-to-bottom** order within each vertical column. A stack (DFS) can process deeper nodes before shallower ones.

---

### 3. Why store Horizontal Distance?

Without HD, we cannot determine which vertical column a node belongs to.

---

### 4. Can we use HashMap?

Yes, but then you'll need to sort the keys separately.

```
HashMap + sort keys

or

TreeMap directly
```

TreeMap is simpler.

---

### 5. Why Pair class?

We need both

```
Node

Horizontal Distance
```

inside the queue.

---

### 6. Difference between Vertical Order and Top View?

Consider

```
        1
       / \
      2   3
       \
        4
```

Vertical Order

```
HD -1 : 2

HD 0 : 1 4

HD +1 : 3
```

Output

```
[[2],[1,4],[3]]
```

Top View

```
2 1 3
```

Only the **first (topmost)** node seen for each HD is included.

---

### 7. Difference between Vertical Order and Bottom View?

Using the same tree:

Vertical Order

```
HD -1 : 2

HD 0 : 1 4

HD +1 : 3
```

Bottom View

```
2 4 3
```

Only the **last (bottommost)** node seen for each HD is included.

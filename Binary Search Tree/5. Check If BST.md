# Problem Statement

Given the root of a binary tree, determine whether it is a **Binary Search Tree (BST)**.

---

# BST Property

For every node:

```
Left Subtree < Root < Right Subtree
```

This property must hold for **every node** in the tree, not just its immediate children.

---

# Example 1 (Valid BST)

```
        20
       /  \
     10    30
    / \    / \
   5  15 25 35
```

Output

```
true
```

---

# Example 2 (Not a BST)

```
        20
       /  \
     10    30
    / \
   5  25
```

Output

```
false
```

Why?

```
25 is in the left subtree of 20.

But

25 > 20

BST property is violated.
```

---

# Important Observation

Many beginners think:

```
Left Child < Parent

Right Child > Parent
```

This is **not sufficient**.

Example

```
        20
       /  \
     10    30
       \
        25
```

Here,

```
25 > 10
```

looks correct.

But

```
25 belongs to the left subtree of 20.

25 > 20

Not a BST.
```

This is why we need a better validation method.

# Approach 1 – Inorder Traversal + ArrayList

## Idea

Property of BST:

> **Inorder Traversal of a BST is always in strictly increasing order.**

Steps:

1. Perform inorder traversal.
2. Store values in an ArrayList.
3. Check if the list is strictly increasing.

---

## Algorithm

```
Inorder Traversal

↓

Store Nodes

↓

Check

list[i] > list[i-1]

↓

BST
```

---

## Code

```java
class Solution {

    ArrayList<Integer> list = new ArrayList<>();

    boolean isBST(Node root) {

        inorder(root);

        for (int i = 1; i < list.size(); i++) {

            if (list.get(i) <= list.get(i - 1))
                return false;
        }

        return true;
    }

    void inorder(Node root) {

        if (root == null)
            return;

        inorder(root.left);

        list.add(root.data);

        inorder(root.right);
    }
}
```

---

## Why `<=` Instead of `<`?

Suppose

```
    5
   /
  5
```

Inorder

```
5 5
```

Using

```
<
```

returns

```
true
```

which is incorrect for a BST that requires **unique values**.

Therefore

```
<=
```

is safer unless the problem explicitly allows duplicates.

---

# Approach 2 – Inorder + Previous Node (Most Asked)

Instead of storing all values, compare the current node with the previously visited node.

---

## Idea

During inorder traversal:

```
Previous Node

↓

Current Node

↓

Current must be greater
```

---

## Algorithm

```
Go Left

↓

Visit Node

↓

Current > Previous ?

↓

Yes

Continue

↓

Go Right
```

---

## Code

```
class Solution {

    Node prev = null;

    boolean isBST(Node root) {

        if (root == null)
            return true;

        if (!isBST(root.left))
            return false;

        if (prev != null && root.data <= prev.data)
            return false;

        prev = root;

        return isBST(root.right);
    }
}
```

---

## Dry Run

Tree

```
      5
     / \
    3   7
   / \ / \
  2 4 6 8
```

|Current|Previous|Valid?|
|---|---|---|
|2|null|✔|
|3|2|✔|
|4|3|✔|
|5|4|✔|
|6|5|✔|
|7|6|✔|
|8|7|✔|

Answer

```
true
```

---

## Time Complexity

```
O(N)
```

## Space Complexity

```
O(H)
```

where **H** is the height of the tree.

# Approach 3 – Min-Max Range (Best Interview Solution)

This is the approach interviewers usually expect because it directly validates the BST definition.

---

## Key Idea

Each node must lie within an allowed range.

Initially:

```
(-∞ , +∞)
```

For the left child:

```
(min , root.data)
```

For the right child:

```
(root.data , max)
```

---

## Visualization

```
              20
          (-∞,∞)

          /      \

 (-∞,20)          (20,∞)

     10              30

  /      \         /      \

(-∞,10) (10,20) (20,30) (30,∞)
```

Every node must satisfy its own range.

---

## Algorithm

```
Current Node

↓

Within Range?

↓

No → False

↓

Yes

↓

Check Left

↓

Check Right
```

---

## Code

```
class Solution {

    boolean isBST(Node root) {
        return helper(root, Long.MIN_VALUE, Long.MAX_VALUE);
    }

    boolean helper(Node root, long min, long max) {

        if (root == null)
            return true;

        if (root.data <= min || root.data >= max)
            return false;

        return helper(root.left, min, root.data)
            && helper(root.right, root.data, max);
    }
}
```

---

## Dry Run

Tree

```
        20
       /  \
     10    30
       \
        25
```

### Root

```
20

Range (-∞,∞)

✔
```

### Node 10

```
Range (-∞,20)

✔
```

### Node 25

```
Range (10,20)

25 > 20

❌

Return False
```

---

## Why Use `long` Instead of `int`?

Suppose a node contains:

```
Integer.MIN_VALUE
```

Using

```
helper(root, Integer.MIN_VALUE, Integer.MAX_VALUE)
```

can fail because comparisons at the boundary become ambiguous.

Using `Long.MIN_VALUE` and `Long.MAX_VALUE` avoids this edge case.

---

```
O(N)
```

## Space Complexity

```
O(H)
```

# Common Mistakes

### Mistake 1

Checking only immediate children.

```
Left Child < Parent

Right Child > Parent
```

This does **not** validate the whole subtree.

---

### Mistake 2

Using `<` instead of `<=`

```
if (list.get(i) < list.get(i - 1))
```

This allows duplicate values.

Use

```
if (list.get(i) <= list.get(i - 1))
```

if duplicates are not allowed.

---

### Mistake 3

Using `Integer.MIN_VALUE` and `Integer.MAX_VALUE` as range limits.

Prefer

```
Long.MIN_VALUE
Long.MAX_VALUE
```

to safely handle boundary values.

---

### Mistake 4

Thinking sorted inorder alone proves a tree is a BST.

It is a valid approach **for validation**, but in interviews the **Min-Max Range** approach is preferred because it directly enforces the BST definition.

---

# Interview Questions

### 1. Why does inorder traversal help?

Because the inorder traversal of a BST always produces values in strictly increasing order.

---

### 2. Which approach is preferred?

The **Min-Max Range** approach is preferred because it validates every node against the allowed range and directly checks the BST property.

---

### 3. Why use `long` for the range?

To safely handle nodes with values equal to `Integer.MIN_VALUE` or `Integer.MAX_VALUE`.

---

### 4. Can duplicates exist in a BST?

It depends on the problem definition. Most interview problems assume **no duplicates**, so comparisons use `<` and `>` (or `<=`/`>=` for validation). If duplicates are allowed, the rule must clearly specify whether they belong in the left or right subtree.

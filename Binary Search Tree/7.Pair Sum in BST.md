
# Pair Sum in BST

---

# 1. Problem Statement

Given a **Binary Search Tree** and an integer **X**, determine whether there exist **two distinct nodes** whose sum equals **X**.

Return

- **true** → Pair exists
- **false** → Pair doesn't exist

---

# 4. Core Intuition ⭐⭐⭐⭐⭐

For every node,

suppose current value is

```
20
```

Need

```
X-20
```

If that value has already been visited,

Pair found.

Otherwise

Store

```

```

Continue traversal.

Exactly the same logic as **Two Sum using HashSet**.

The BST property is **not actually required** for this approach. The same idea also works for a normal Binary Tree.

# Why Inorder?

Many candidates ask this.

Answer

> **It doesn't have to be inorder.**

You can use

- Preorder
- Inorder
- Postorder

because **HashSet lookup is independent of traversal order**.

GFG uses inorder simply because the problem belongs to the BST section.

This is an excellent interview point.

---

# Algorithm

```
Create HashSet

Traverse Tree

If node is null

return false

Visit Left

If target-current exists

return true

Insert current

Visit Right

If found anywhere

return true

Else

return false
```

---

# Code (Your GFG Solution)

```java
class GFG {

    static boolean findPair(Node root, int X) {

        TreeSet<Integer> set = new TreeSet<>();

        return inorder(root, X, set);
    }

    static boolean inorder(Node root,
                           int X,
                           TreeSet<Integer> set) {

        if (root == null)
            return false;

        // Search left subtree
        if (inorder(root.left, X, set))
            return true;

        // Check complement
        if (set.contains(X - root.data))
            return true;

        // Store current value
        set.add(root.data);

        // Search right subtree
        return inorder(root.right, X, set);
    }
}
```

Time

```

```


# Why TreeSet Works?

GFG uses

```

```

Could also use

```

```

### HashSet

Lookup

```
O(1)
```

Average

Preferred in interviews.

---

### TreeSet

Lookup

```
O(logN)
```

Implemented using a Red-Black Tree.

Works correctly.

Slightly slower.

---

Interview Answer

> "I'd use HashSet because it provides average O(1) lookup, while TreeSet gives O(log N) lookup and is only needed if sorted-order operations are required."

### Q1. Why use a Set?

To check whether the complement (`X - current`) has already been seen in constant time.

---

### Q2. Why use inorder?

For the HashSet approach, **it's not required**. Any traversal order works. Inorder is often chosen because the input is a BST.

---

### Q3. Can this work for a Binary Tree?

**Yes.** The HashSet solution is independent of BST ordering.

---

### Q4. Which Set would you choose?

**HashSet**, because average lookup is **O(1)**.

---

### Q5. Can you reduce space?

**Yes.** Use two BST iterators (forward and reverse inorder) to simulate two pointers with **O(H)** extra space.

Given the **root** of a **[binary search tree](https://www.geeksforgeeks.org/binary-search-tree-data-structure/ "BST")** and a number **k**, find the **greatest** number in the binary search tree that is less than or equal to **k**.

**Note:** If no such node value exists that is smaller than _k_, then return **-1**.

**Examples:**

**Input:** root = [10, 7, 15, 2, 8, 11, 16],  k  =  14  
![](https://media.geeksforgeeks.org/img-practice/prod/addEditProblem/895571/Web/Other/blobid3_1747652897.jpg)  
**Output:** 11
**Explanation:** The greatest element in the tree which is less than or equal to 14, is 11.

**Input:** root = [5, 2, 12, 1, 3, 9, 21, N, N, N, N, N, N, 19, 25],  k  = 24  
![](https://media.geeksforgeeks.org/img-practice/prod/addEditProblem/895571/Web/Other/blobid0_1747652607.jpg)  
**Output:** 21
**Explanation:** The greatest element in the tree which is less than or equal to 24, is 21.

### Definition

The **Floor** of `X` is:

> **The greatest value in the BST that is less than or equal to X.**

If no such value exists, return **-1** (or `null`, depending on the problem statement).

# BST Property

```
        Root

Left < Root < Right
```

This property allows us to search efficiently.

# Brute Force Approach

Traverse the entire tree.

For every node


### Case 1

```
Node == X
```

Answer found immediately.

Return node.

---

### Case 2

```
Node < X
```

Possible floor.

Store it.

Move right.

---

### Case 3

```
Node > X
```

Too large.

Move left.

# Algorithm

```
Start at Root

↓

Node == X ?

↓

Yes

Return Node

↓

No

↓

Node < X ?

↓

Store Node

Move Right

↓

Else

Move Left

↓

Repeat
```

# Iterative Solution (Most Preferred in Interviews)

```
class Solution {

    int floor(Node root, int x) {

        int floor = -1;

        while (root != null) {

            if (root.data == x)
                return root.data;

            if (root.data < x) {

                floor = root.data;
                root = root.right;

            } else {

                root = root.left;
            }
        }

        return floor;
    }
}
```

# Recursive Solution

```
class Solution {

    int floor = -1;

    int findFloor(Node root, int x) {

        helper(root, x);

        return floor;
    }

    void helper(Node root, int x) {

        if (root == null)
            return;

        if (root.data == x) {
            floor = root.data;
            return;
        }

        if (root.data < x) {

            floor = root.data;
            helper(root.right, x);

        } else {

            helper(root.left, x);
        }
    }
}
```

---

# Why Move Right When `node.data < X`?

Example

```
         20
           \
            25
              \
               27
```

Find Floor of

```
28
```

20 is a possible answer.

But 27 is a **better floor**.

Therefore, after storing 20, search the right subtree for a larger valid value.

---

# Why Move Left When `node.data > X`?

Example

```
        30
       /
      20
```

Find Floor of

```
28
```

30 is too large.

The floor must be smaller.

So move left.

# Floor vs Ceil

|Floor|Ceil|
|---|---|
|Greatest value ≤ X|Smallest value ≥ X|
|If node < X → Go Right|If node < X → Go Right (cannot be ceil yet)|
|If node > X → Go Left|If node > X → Store candidate and Go Left|

# Common Mistakes

### Mistake 1

Searching both left and right subtrees.

❌ Wrong.

A BST lets you discard half of the tree at every step.

---

### Mistake 2

Not updating the floor before moving right.

Wrong

```
root = root.right;
```

Correct

```
floor = root.data;
root = root.right;
```

---

### Mistake 3

Returning immediately when

```
node.data < X
```

There may be a larger valid value in the right subtree.

---

### Mistake 4

Using binary search logic on a normal binary tree.

This optimization works **only for BSTs**.

# Interview Questions

### 1. What is the floor of a BST?

The floor is the greatest value in the BST that is less than or equal to the given key.

---

### 2. Why is the optimized solution `O(log N)`?

In a balanced BST, each comparison eliminates half of the remaining tree, similar to binary search.

---

### 3. Why do we move right when `node.data < X`?

The current node is a valid floor candidate, but there might be a larger value (still ≤ X) in the right subtree.

---

### 4. Why do we move left when `node.data > X`?

The current node is too large to be the floor, so any valid floor must be in the left subtree.

---

### 5. Which approach is preferred in interviews?

The **iterative solution** is usually preferred because it is simple, uses **O(1)** extra space, and clearly demonstrates understanding of BST properties.

# Ceil of a BST 
The **Ceil of a Binary Search Tree (BST)** is one of the **most frequently asked BST interview questions**. It is the opposite of the **Floor** problem.

---

# Problem Statement

Given the root of a **Binary Search Tree (BST)** and a key `X`, find the **Ceil** of `X`.

### Definition

The **Ceil** of `X` is:

> **The smallest value in the BST that is greater than or equal to X.**

If no such value exists, return **-1** (or `null`, depending on the problem statement).

```
         Root

Left < Root < Right
```

# Key Idea

### Case 1

```
Node == X
```
Current node is the ceil.
Return immediately.

---
### Case 2

```
Node < X
```
Too small.
Move right.

---
### Case 3

```
Node > X
```

Possible ceil.
Store it.
Move left.

---

# Algorithm

```
Start at Root

↓

Node == X ?

↓

Yes

Return Node

↓

Node > X ?

↓

Store Node

Move Left

↓

Else

Move Right

↓

Repeat
```

# Iterative Solution (Most Preferred)

```java
class Solution {

    int ceil(Node root, int x) {

        int ceil = -1;

        while (root != null) {

            if (root.data == x)
                return root.data;

            if (root.data > x) {

                ceil = root.data;
                root = root.left;

            } else {

                root = root.right;
            }
        }

        return ceil;
    }
}
```

# Recursive Solution

```
class Solution {

    int ceil = -1;

    int findCeil(Node root, int x) {

        helper(root, x);

        return ceil;
    }

    void helper(Node root, int x) {

        if (root == null)
            return;

        if (root.data == x) {
            ceil = root.data;
            return;
        }

        if (root.data > x) {

            ceil = root.data;
            helper(root.left, x);

        } else {

            helper(root.right, x);
        }
    }
}
```

# Why Move Left When `node.data > X`?

Example

```
        30
       /
      25
```

Find Ceil of

```
24
```

30 is a possible ceil.

But 25 is a **better (smaller)** ceil.

So we:

- Store 30
- Move left to search for a smaller valid candidate

---

# Why Move Right When `node.data < X`?

Example

```
      20
        \
         25
```

Find Ceil of

```
24
```

20 is too small.

The ceil must be larger.

So move right.

---

# Floor vs Ceil

|Floor|Ceil|
|---|---|
|Greatest value ≤ X|Smallest value ≥ X|
|If node < X → Store & Go Right|If node < X → Go Right|
|If node > X → Go Left|If node > X → Store & Go Left|

---

# Floor vs Ceil Decision Table

|Condition|Floor|Ceil|
|---|---|---|
|`node == X`|Return node|Return node|
|`node < X`|Store node, go right|Go right|
|`node > X`|Go left|Store node, go left|

---

# Common Mistakes

### Mistake 1

Updating the ceil when

```
node < X
```

Wrong.

The current node is too small.

---

### Mistake 2

Returning immediately after finding

```
node > X
```

Wrong.

There may be a smaller valid value in the left subtree.

---

### Mistake 3

Searching both subtrees.

Wrong.

Use the BST property to eliminate half of the search space.

---

### Mistake 4

Using this algorithm on a normal binary tree.

The optimization works **only for BSTs**.

---

# Interview Questions

### 1. What is the ceil of a BST?

The ceil is the smallest value in the BST that is greater than or equal to the given key.

---

### 2. Why do we move left after finding a candidate?

Because there may be a smaller value in the left subtree that is still greater than or equal to the key, giving a better ceil.

---

### 3. Why don't we store values when `node.data < X`?

Because such values are too small to be the ceil.

---

### 4. Why is the optimized approach `O(log N)`?

A balanced BST eliminates half of the remaining nodes at each step, just like binary search.

---

### 5. Which solution is preferred in interviews?

The **iterative approach** because it is simple, efficient, and uses **O(1)** extra space.

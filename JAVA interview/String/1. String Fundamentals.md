# 1. What is String?

A **String** is a sequence of characters used to represent text.

In Java, a String is **not a primitive data type**. It is an object of the `String` class.

Example:

```
String name = "Manish";
```

Here,

- `"Manish"` → String Literal
- `name` → Reference Variable
- `String` → Class

---

## Memory Diagram

```
Stack                    Heap (String Pool)

+------+                 +----------------+
| name |---------------> |   "Manish"     |
+------+                 +----------------+
```

---

## Different Ways to Create String

### Method 1: String Literal (Recommended)

```
String s1 = "Hello";
```

Stored in the **String Constant Pool (SCP)**.

---

### Method 2: Using `new`

```
String s2 = new String("Hello");
```

Creates:

- One object in the String Pool (if not already present)
- One object in the Heap

---

### Method 3: Empty String

```
String s = "";
```

---

### Method 4: Character Array

```
char[] arr = {'J', 'a', 'v', 'a'};

String s = new String(arr);
```

---

# Interview Definition

> A String in Java is an immutable object that represents a sequence of characters. It is implemented by the `java.lang.String` class and supports efficient memory usage through the String Constant Pool.

# 2. Why is String a Class and Not a Primitive?

Java has only 8 primitive types:

```
byte
short
int
long
float
double
char
boolean
```

Text can vary in length, so Java cannot represent it using a primitive.

Example

```
"Java"
"Hello World"
"OpenAI"
```

Each has a different length.

---

## Advantages of Making String a Class

### 1. Methods

```
String s = "Java";

s.length();

s.substring(1);

s.charAt(0);

s.toUpperCase();
```

If String were primitive:

```
"Java".length();
```

would not be possible.

---

### 2. Object-Oriented Programming

Since String is a class:

- Objects
- Methods
- Constructors
- Interfaces
- Polymorphism

all become possible.

---

### 3. Security

Strings are used in:

- Usernames
- Passwords
- URLs
- Database Connections
- File Paths

Having String as a class allows Java to provide controlled behavior.

---

### 4. Memory Optimization

Objects enable the use of the **String Constant Pool**.

---

## Interview Answer

> Strings are classes because text is variable in size and requires many utility methods such as `length()`, `substring()`, and `replace()`. As a class, String can also support immutability, the String Constant Pool, object-oriented features, and better security.

# 3. Why is String Final?

Declaration

```
public final class String
```

The `final` keyword means:

```
Cannot be inherited.
```

---

## Why?

### Reason 1: Security

Suppose inheritance were allowed.

```
class MyString extends String {

}
```

A subclass could override methods.

Example

```
charAt()

hashCode()

equals()
```

This could break Java's internal behavior.

---

### Reason 2: Immutability

If inheritance were allowed:

```
class MyString extends String {

    void change() {

    }

}
```

Someone could modify internal state.

Immutability would be compromised.

---

### Reason 3: HashMap Reliability

Strings are commonly used as keys.

```
HashMap<String, Integer>
```

If String changed after insertion:

```
Hash changes

↓

Bucket changes

↓

Object cannot be found
```

---

### Reason 4: Thread Safety

Immutable objects are naturally thread-safe.

---

## Interview Answer

> String is final to prevent inheritance. This ensures immutability, maintains consistent implementations of methods like `equals()` and `hashCode()`, provides thread safety, and guarantees reliable behavior when Strings are used as keys in collections such as `HashMap`.

---

# 4. Why is String Immutable?

Once a String object is created,

its value **cannot be changed**.

---

## Example

```
String s = "Java";

s.concat(" Programming");

System.out.println(s);
```

Output

```
Java
```

---

Correct way

```
s = s.concat(" Programming");
```

Output

```
Java Programming
```

---

## Memory Diagram

Before

```
Stack              String Pool

s -------------> "Java"
```

After

```
s = s.concat(" Programming");
```

```
Stack              String Pool

s -------------> "Java Programming"

                 "Java"
```

The original object remains unchanged.

---

# Why Did Java Make String Immutable?

### 1. Security

Used in:

- URLs
- Database credentials
- File paths
- Network connections

Changing them after creation could introduce security issues.

---

### 2. String Pool

Because Strings never change,

multiple references can safely point to the same object.

```
String s1 = "Java";

String s2 = "Java";
```

Both refer to the same pooled object.

---

### 3. Thread Safety

Multiple threads can share the same String without synchronization.

---

### 4. Hashing

Hash code is computed once and reused.

This makes operations like `HashMap` lookups faster.

---

# Interview Answer

> Strings are immutable to improve security, enable String Pool sharing, support thread safety, and allow efficient caching of hash codes. Any operation that appears to modify a String actually creates a new String object.

# 6. Internal Structure of String

## Java 8

Internally,

```
private final char[] value;
```

Memory

```
String Object

↓

char[]

↓

J

a

v

a
```

---

## Java 9+

To save memory, Java stores characters using:

```
private final byte[] value;
```

along with

```
private final byte coder;
```

where:

- `coder = 0` → Latin-1 (1 byte per character)
- `coder = 1` → UTF-16 (2 bytes per character)

---

## Why?

Many strings contain only ASCII/Latin-1 characters.

Example

```
Hello

Java

OpenAI
```

These can be stored using **1 byte per character**, reducing memory usage.

---

# Memory Comparison

Suppose

```
Hello
```

### Java 8

```
char[]

2 bytes × 5

=

10 bytes
```

---

### Java 9+

```

1 byte × 5

=

5 bytes
```

Approximately **50% memory savings** for Latin-1 strings.

# 7. Evolution of String (Java 8 vs Java 9+)

|Feature|Java 8|Java 9+|
|---|---|---|
|Internal Storage|`char[]`|`byte[]` + `coder`|
|Memory Usage|Higher|Lower for Latin-1 strings|
|Compact Strings|❌ No|✅ Yes|
|Performance|Good|Better memory efficiency|
|Public API|Same|Same|

---

## Compact Strings (Java 9)

The change to `byte[]` with a `coder` field is known as **Compact Strings**.

Benefits:

- Lower memory consumption
- Better cache utilization
- No changes required in application code

# Common Interview Questions

### 1. Is String primitive or object?

Object.

---

### 2. Why is String final?

To prevent inheritance, preserve immutability, ensure security, and maintain reliable behavior of methods like `equals()` and `hashCode()`.

---

### 3. Why is String immutable?

To enable the String Pool, improve security, provide thread safety, and cache hash codes efficiently.

---

### 4. Why can String literals be shared?

Because immutable objects cannot be modified, multiple references can safely point to the same pooled object.

---

### 5. What changed internally in Java 9?

The internal storage changed from `char[]` to `byte[]` with a `coder` field, enabling **Compact Strings** and reducing memory usage for Latin-1 text.

# Common Mistakes

### Mistake 1

Thinking `concat()` changes the original String.

```
String s = "Java";

s.concat("8");
```

`"Java"` remains unchanged.

---

### Mistake 2

Assuming every `new String()` uses only one object.

It typically creates:

- A pooled literal (if not already present)
- A separate heap object

---

### Mistake 3

Believing `final` makes String immutable.

`final` prevents inheritance.

Immutability comes from the internal implementation (private final fields, no mutator methods, defensive behavior).

# 2-Minute Interview Answer

> A String in Java is an immutable object of the `java.lang.String` class that represents a sequence of characters. It is a class rather than a primitive because text has variable length and requires rich functionality such as `substring()`, `replace()`, and `compareTo()`. The `String` class is declared `final` to prevent inheritance, which helps preserve immutability and ensures the correctness of methods like `equals()` and `hashCode()`. Immutability improves security, enables the String Constant Pool, makes Strings naturally thread-safe, and allows hash code caching. Internally, Java 8 stored characters in a `char[]`, while Java 9 introduced Compact Strings, using a `byte[]` with a `coder` field to reduce memory usage for Latin-1 strings without changing the public API.

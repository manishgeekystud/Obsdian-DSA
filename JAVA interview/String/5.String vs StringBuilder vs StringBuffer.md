# 1. Introduction

Java provides three classes for handling text:

```
String

StringBuilder

StringBuffer
```

Although all store character data, they differ significantly in **mutability, synchronization, performance, and use cases**.

---

# Real-Life Analogy

Imagine writing on paper.

### String

```
Every correction

↓

Throw away old paper

↓

Write on a new paper
```

Every modification creates a **new object**.

---

### StringBuilder

```
One Notebook

↓

Erase

↓

Write Again

↓

Same Notebook
```

The same object is modified.

---

### StringBuffer

Same as StringBuilder,

but

```
One Person Writes

↓

Others Wait
```

because operations are synchronized.

# 2. What is String?

`String` is an **immutable** class.

Once created,

its value **cannot change**.

Example

```
String s = "Java";

s.concat(" Programming");

System.out.println(s);
```

Output

```
Java
```

Why?

```
concat()

↓

Creates New Object

↓

Old Object Unchanged
```

---

## Memory Diagram

```
Before

s -------> "Java"
```

After

```
s = s.concat(" Programming");
```

```
s -------> "Java Programming"

"Java" still exists.
```

---

# 3. What is StringBuilder?

`StringBuilder` is a **mutable** class.

Changes happen on the **same object**.

Example

```
StringBuilder sb = new StringBuilder("Java");

sb.append(" Programming");

System.out.println(sb);
```

Output

```
Java Programming
```

No new object is created for `append()`.

---

## Memory Diagram

```
Before

sb

↓

Java
```

After

```
sb

↓

Java Programming
```

Same object.

---

# 4. What is StringBuffer?

`StringBuffer` is also **mutable**.

Difference:

Its methods are **synchronized**.

Example

```
StringBuffer sb = new StringBuffer("Java");

sb.append(" Programming");
```

Same object is modified.

---

# 5. Mutable vs Immutable

## Mutable

Object can change.

Example

```

```

Object becomes

```

```

---

## Immutable

Cannot change.

Example

```
String s = "Java";

s.concat("8");
```

Creates

```

```


# 8. Performance

## String

Every modification

```
Old Object

↓

New Object

↓

Garbage Collection
```

Many temporary objects are created.

---

## Example

```
String s = "";

for(int i=0;i<1000;i++)
{
    s += i;
}
```

Creates

```
1000+

Objects
```

Very inefficient.

---

## StringBuilder

```
StringBuilder sb = new StringBuilder();

for(int i=0;i<1000;i++)
{
    sb.append(i);
}
```

Same object.

Much faster.

---

## StringBuffer

Also modifies the same object.

Slightly slower because every method is synchronized.

# When Should You Use Each?

## Use String

When:

- Text doesn't change
- Constants
- Configuration values
- Keys in `HashMap`

Example

```
String country = "India";
```

---

## Use StringBuilder

When:

- Frequent modifications
- Single-threaded applications
- Building SQL queries
- Creating JSON/XML
- Loops

Example

```
StringBuilder sb = new StringBuilder();

for(int i=0;i<1000;i++)
{
    sb.append(i);
}
```

---

## Use StringBuffer

When:

- Multiple threads modify the same text
- Thread safety is required

Example

```
StringBuffer log = new StringBuffer();

log.append("Started");
```

# Common Interview Questions

## 1. Which is faster?

```
StringBuilder
```

because it has no synchronization overhead.

---

## 2. Why is StringBuffer slower?

Every public modifying method is synchronized.

Locking introduces overhead.

---

## 3. Which is thread-safe?

```
String

StringBuffer
```

---

## 4. Is StringBuilder thread-safe?

No.

---

## 5. Why is String thread-safe?

Because it is immutable.

---

## 6. Which one uses the String Constant Pool?

Only

```
String
```

---

## 7. Which one should be used in loops?

Always

```
StringBuilder
```

instead of repeated String concatenation.

---

## 8. Does `append()` create a new object?

No.

It modifies the same `StringBuilder` or `StringBuffer` instance.

# Common Mistakes

### Mistake 1

Using String inside loops

```
String s = "";

for(int i=0;i<1000;i++)
{
    s += i;
}
```

Creates many temporary objects.

Prefer `StringBuilder`.

---

### Mistake 2

Using `StringBuffer` everywhere.

If your code is single-threaded, `StringBuilder` is usually the better choice.

---

### Mistake 3

Thinking `StringBuilder` uses the String Pool.

It doesn't. Only `String` literals participate in the String Constant Pool.

---

### Mistake 4

Thinking immutable means slow.

For read-only operations, immutable Strings are efficient because of pooling and hash-code caching. They become inefficient only when repeatedly modified.

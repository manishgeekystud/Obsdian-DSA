

This is the **most frequently asked String topic** in Java interviews. Almost every interviewer asks questions like:

- How many objects are created?
- Where are they stored?
- Explain String Constant Pool.
- Difference between `String s = "Java"` and `new String("Java")`.
- What happens internally when a String literal is encountered?

---

# Memory Areas Involved

When working with Strings, two memory areas are important:

```
JVM Memory

│

├── Heap Memory
│      │
│      ├── Normal Objects
│      └── String Constant Pool (SCP)
│
└── Stack Memory
       │
       └── Local Variables (References)
```

---

# 1. Heap Memory

The **Heap** is the runtime memory where all Java objects are created.

Examples

```
Employee emp = new Employee();

String s = new String("Java");
```

Both objects are created in the Heap.

Characteristics

- Shared by all threads
- Managed by Garbage Collector
- Objects are dynamically allocated

---

# Heap Memory Diagram

```
Stack                      Heap

+-----+               +------------------+
| emp |-------------->| Employee Object  |
+-----+               +------------------+
```

---

# 2. String Constant Pool (SCP)

The **String Constant Pool** is a special area inside the Heap that stores **String literals**.

Purpose:

- Avoid duplicate String objects
- Save memory
- Improve performance

Example

```
String s1 = "Java";
String s2 = "Java";
```

Only **one String object** is created.

---

## Memory Diagram

```
Stack                     String Pool

+-----+               +---------------+
| s1  |-------------->|   "Java"      |
+-----+               +---------------+
| s2  |----------------------^
+-----+
```

Both references point to the **same object**.

---

# Why Does the JVM Use the String Pool?

Without pooling:

```
String s1 = "Java";
String s2 = "Java";
String s3 = "Java";
```

Three identical objects would be created.

With the pool:

```
One Object

↓

Three References
```

Memory is saved.

---

# 3. String Literal

A String written inside double quotes is called a **String Literal**.

Example

```
String s = "Java";
```

Process:

1. JVM checks the String Pool.
2. If `"Java"` exists, reuse it.
3. Otherwise, create it in the pool.
4. `s` points to that pooled object.

---

## Memory Diagram

```
Stack                  String Pool

+-----+
| s   |-----------------> "Java"
+-----+
```

Objects Created:

```
1
```

# 4. Using `new String()`

Example

```
String s = new String("Java");
```

What happens?

Step 1:

JVM checks the pool.

If `"Java"` is absent:

```
Create in Pool
```

Step 2:

Creates another object using `new`.

```
Heap Object
```

+----------------+

```
2
```

(If `"Java"` was not already present.)

# 8. String Pool Lookup

Whenever JVM encounters

```
"Java"
```

it performs:

```
Literal Found?

↓

Yes

↓

Reuse Existing Object

-------------------

No

↓

Create New Pool Object
```

This process is called **Pool Lookup**.

---

# 9. JVM Handling of String Literals

Example

```
String s = "Java";
```

Internally:

Step 1

Search Pool

```
Is "Java" Present?
```

Step 2

If YES

```
Reuse
```

Step 3

If NO

```
Create in Pool
```

Step 4

Assign reference

# Q4. Why is the String Pool Needed?

- Reduce duplicate objects
- Save memory
- Improve performance
- Enable String sharing

---

# Q5. Is String Pool Part of Heap?

Yes.

From Java 7 onwards:

```
Heap

↓

String Constant Pool
```

Before Java 7, the pool was in the **Permanent Generation (PermGen)**. Since Java 7, it resides in the regular Heap.

---

# Common Mistakes

### Mistake 1

Thinking

```
String s = new String("Java");
```

creates only one object.

Wrong.

Normally

```
Pool

+

Heap
```

Two objects are created (if the literal wasn't already in the pool).

---

### Mistake 2

Thinking every literal creates a new object.

Wrong.

Duplicate literals are reused from the String Pool.

---

### Mistake 3

Believing the String Pool is outside the Heap.

Correct for modern Java:

```
Heap

↓

String Constant Pool
```

# Interview Summary Table

|Code|Pool Objects|Heap Objects|Total Objects|
|---|---|---|---|
|`String s = "Java";`|1|0|1|
|`String s1 = "Java"; String s2 = "Java";`|1|0|1|
|`String s = new String("Java");` _(literal absent)_|1|1|2|
|`String s1 = new String("Java"); String s2 = new String("Java");` _(literal absent initially)_|1|2|3|
|`String s1 = "Java"; String s2 = new String("Java");`|1|1|2|
|`String s1 = new String("Java"); String s2 = "Java";` _(literal absent initially)_|1|1|2|

> **Note:** If the literal is **already present** in the String Constant Pool (because it was loaded earlier), no new pool object is created—only the `new String(...)` heap object is allocated.

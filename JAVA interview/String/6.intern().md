# 1. What is `intern()`?

`intern()` is a method of the `String` class that returns a **reference to the String Constant Pool (SCP)**.

Method signature:

```
public native String intern();
```

- It is a **native** method (implemented in JVM/native code).
- It ensures that only one pooled copy of a String with the same content exists.

---

## Official Definition

> The `intern()` method returns a canonical representation of the String from the String Constant Pool. If the String already exists in the pool, its reference is returned; otherwise, the String is added to the pool and its pooled reference is returned.

---

# 2. Why Do We Use `intern()`?

The main reasons are:

- Reduce duplicate String objects
- Save memory
- Reuse pooled Strings
- Improve reference equality (`==`) for equal String values

---

## Example Without `intern()`

```
String s1 = new String("Java");
String s2 = new String("Java");

System.out.println(s1 == s2);
```

Output

```
false
```

Reason:

Each `new String()` creates a different Heap object.

---

```
+-----------+      +-----------+

String Pool

+-----------+

```

# 3. Using `intern()`

```
String s1 = new String("Java");
String s2 = s1.intern();

System.out.println(s1 == s2);
```

Output

```
false
```

Why?

- `s1` → Heap object
- `s2` → Pool object

Different references.

---

## Memory Diagram

```
Stack

s1 ---------> Heap Object

s2 ---------> Pool Object

Heap
+----------------+
| new String()   |
+----------------+

String Pool
+----------------+
|    "Java"      |
+----------------+
```

# 4. How `intern()` Works Internally

Suppose

```
String s = new String("Hello");

String t = s.intern();
```

JVM performs the following steps:

```
Heap Object Created

↓

Search String Pool

↓

Already Exists?

↓

YES ---------------------> Return Existing Pool Reference

↓

NO

↓

Add String to Pool

↓

Return Pool Reference
```

# 5. Memory Changes After `intern()`

## Before `intern()`

```
String s = new String("Java");
```

Memory

```
Stack

s

↓

Heap

new String("Java")

↓

Pool

"Java"
```

References:

- `s` → Heap object

---

## After `intern()`

```
String p = s.intern();
```

Memory

```
Stack

s ---------> Heap Object

p ---------> Pool Object
```

The Heap object still exists.

`intern()` does **not** delete it.

# 6. Does `intern()` Create a New Object?

### Case 1

Pool already contains the String

```

s.intern();
```

Objects created

```

Heap : 1

New Objects : 0
```

---

### Case 2

Pool does not contain the String

```
String s = new String("OpenAI");

s.intern();
```

Objects

```

Heap : 1
```

# 8. Java 6 vs Java 7+

This is a popular interview topic.

## Java 6

The String Pool was stored in **PermGen**.

Calling `intern()` copied the String into the pool.

```
Heap Object

↓

Copy to PermGen Pool
```

---

## Java 7+

The String Pool moved into the **Heap**.

When the String is not already present, the JVM can place the pooled reference in the pool instead of creating an unnecessary duplicate object.

```
Heap

↓

String Pool (also in Heap)

↓

Reference reused
```

This reduces memory overhead.

---

# 9. Performance Benefits

Using `intern()`:

- Reduces duplicate Strings
- Saves Heap memory
- Improves memory efficiency for repeated values
- Can make `==` comparisons succeed when both references point to the pooled object

---

# When Should You Use `intern()`?

Useful when:

- Millions of duplicate Strings exist
- Parsing XML/JSON
- Processing log files
- Reading dictionaries
- Large datasets with repeated values

Example

```
String city = new String("Bangalore").intern();
```

Repeated `"Bangalore"` values can share the same pooled object.

---

# When Should You Avoid `intern()`?

Avoid using it unnecessarily:

- For small applications
- When Strings are mostly unique
- Inside performance-critical loops without a clear need

Maintaining the pool also has overhead.

---

# Common Interview Questions

## 1. What is `intern()`?

It returns the canonical pooled reference of a String from the String Constant Pool.

---

## 2. Does `intern()` create a new object?

Only if an equivalent String is not already present in the pool.

---

## 3. Where is the object returned by `intern()` stored?

In the **String Constant Pool**, which has been part of the Heap since Java 7.

---

## 4. Does `intern()` delete the Heap object?

No.

The Heap object remains until it becomes unreachable and is garbage collected.

---

## 5. What is the return type of `intern()`?

```
String
```

---

## 6. Why is `intern()` useful?

It reduces duplicate Strings, saves memory, and allows equal Strings to share a single pooled object.

---

## 7. Is `intern()` commonly used in business applications?

Usually **no**. Most applications rely on String literals and normal JVM optimizations. `intern()` is mainly useful in specialized scenarios with a very large number of duplicate Strings.

String comparison is one of the **most frequently asked Java interview topics**. Interviewers often test whether you understand the difference between **reference comparison** and **content comparison**.

Typical questions include:

- What is the difference between `==` and `equals()`?
- When should you use `equals()`?
- What is `compareTo()`?
- What is lexicographical comparison?
- What is `equalsIgnoreCase()`?
- What is `compareToIgnoreCase()`?

---

# 1. `==` Operator

## Definition

The `==` operator compares **references (memory addresses)**, **not the contents** of String objects.

If both references point to the **same object**, it returns `true`; otherwise, it returns `false`.

---

## Example 1 (String Literals)

```
String s1 = "Java";
String s2 = "Java";

System.out.println(s1 == s2);
```

Output

```
true
```

### Why?

Both variables refer to the same object in the **String Constant Pool**.

Memory Diagram

```
Stack                     String Pool

s1 -----------|

               |-------> "Java"

s2 -----------|
```

---

## Example 2 (`new String()`)

```
String s1 = new String("Java");
String s2 = new String("Java");

System.out.println(s1 == s2);
```

Output

```
false
```

### Why?

Each `new String()` creates a different object in the Heap.

Memory Diagram

```
Heap

+---------+      +---------+

| "Java"  |      | "Java"  |

+---------+      +---------+

     ^                 ^

    s1                s2
```

Different references → `false`

---

## Example 3

```
String s1 = "Java";
String s2 = new String("Java");

System.out.println(s1 == s2);
```

Output

```
false
```

Reason:

- `s1` → String Pool
- `s2` → Heap

Different objects.

---

## Interview Answer

> `==` compares object references. It checks whether two references point to the same object in memory, not whether their contents are equal.

---

# 2. `equals()`

## Definition

`equals()` compares the **contents (characters)** of two Strings.

---

## Example

```
String s1 = new String("Java");
String s2 = new String("Java");

System.out.println(s1.equals(s2));
```

Output

```
true
```

Although the references are different, the contents are identical.

---

## Example

```
String s1 = "Java";
String s2 = "Python";

System.out.println(s1.equals(s2));
```

Output

```
false
```

---

## Memory

```
Heap

s1 -----> "Java"

s2 -----> "Java"
```

Different objects

Same content

Result

```
true
```

---

## Internal Working (Simplified)

```
if (length != other.length)
    return false;

compare each character

if all characters match
    return true
else
    return false
```

---

## Interview Answer

> `equals()` compares the actual sequence of characters stored in the String.

---

# 3. `equalsIgnoreCase()`

## Definition

Compares two Strings while **ignoring uppercase and lowercase differences**.

---

## Example

```
String s1 = "JAVA";
String s2 = "java";

System.out.println(s1.equalsIgnoreCase(s2));
```

Output

```
true
```

---

## Example

```
String s1 = "Java";
String s2 = "Python";

System.out.println(s1.equalsIgnoreCase(s2));
```

Output

```
false
```

---

## Interview Use Cases

Useful for:

- Login systems
- User input
- Command-line options
- Searching

---

# 4. `compareTo()`

## Definition

Compares two Strings **lexicographically (dictionary order)**.

Returns:

- `0` → Equal
- Positive → Current String is greater
- Negative → Current String is smaller

---

## Example

```
System.out.println("Apple".compareTo("Apple"));
```

Output

```
0
```

---

## Example

```
System.out.println("Cat".compareTo("Bat"));
```

Output

```
1
```

Reason

```
C > B
```

---

## Example

```
System.out.println("Bat".compareTo("Cat"));
```

Output

```
-1
```

---

## Example

```
System.out.println("Java".compareTo("Java Programming"));
```

Output

```
-12
```

Explanation:

The common prefix `"Java"` matches, then one string ends. The comparison is effectively between the string terminator (`'\0'`) and the next character `' '` (space, ASCII/Unicode value 32), so the result is `0 - 32 = -32`? Actually, Java compares the first differing characters. `"Java"` ends after `'a'`, while the other string has a space `' '` next. The comparison is between the end of the first string (treated by the implementation as length difference after matching prefix), and the specified return value is **`4 - 16 = -12`**, because `compareTo()` returns the difference in lengths when one string is a prefix of the other? **No.**

**Correct explanation:** When one string is a prefix of the other, `compareTo()` returns the difference between their lengths only after all compared characters match. Here:

- `"Java".length()` = 4
- `"Java Programming".length()` = 16

So the result is:

```
4 - 16 = -12
```

---

# 5. `compareToIgnoreCase()`

Works exactly like `compareTo()`, but ignores case differences.

---

## Example

```
System.out.println("JAVA".compareToIgnoreCase("java"));
```

Output

```
0
```

---

## Example

```
System.out.println("Apple".compareToIgnoreCase("banana"));
```

Output

```
negative
```

Because

```
Apple < Banana
```

after ignoring case.

---

# 6. Lexicographical Comparison

## Definition

Lexicographical order is **dictionary order**.

Comparison is performed character by character using Unicode values.

---

## Example

```
Apple

Ball

Cat

Dog

Elephant
```

---

## Character Comparison

```
'A' = 65

'B' = 66

'C' = 67
```

Therefore

```
Apple < Ball
```

---

## Example

```
System.out.println("Cat".compareTo("Car"));
```

Comparison

```
C == C

a == a

t > r
```

Output

```
positive
```

---

## Example

```
System.out.println("Car".compareTo("Cat"));
```

Output

```
negative
```

---

# Unicode Comparison

```
System.out.println("A".compareTo("a"));
```

Output

```
-32
```

Reason

```
'A' = 65

'a' = 97

65 - 97 = -32
```

# Comparison Table

|Method|Compares|Case Sensitive|Return Type|
|---|---|---|---|
|`==`|Reference|Yes|`boolean`|
|`equals()`|Content|Yes|`boolean`|
|`equalsIgnoreCase()`|Content|No|`boolean`|
|`compareTo()`|Lexicographical order|Yes|`int`|
|`compareToIgnoreCase()`|Lexicographical order|No|`int`|

---

# `==` vs `equals()`

|Feature|`==`|`equals()`|
|---|---|---|
|Checks|Reference|Content|
|Return Type|`boolean`|`boolean`|
|Compares Memory Address|Yes|No|
|Compares Characters|No|Yes|
|Used for String Content|No|Yes|

---

# `equals()` vs `compareTo()`

|Feature|`equals()`|`compareTo()`|
|---|---|---|
|Returns|`boolean`|`int`|
|Checks Equality|Yes|Yes (when result is `0`)|
|Ordering|No|Yes|
|Sorting Support|No|Yes|

---

# Common Interview Questions

### 1. Why is `==` sometimes `true` for Strings?

Because String literals are stored in the **String Constant Pool**, and identical literals share the same object.

---

### 2. When should you use `equals()`?

Whenever you want to compare the **contents** of two Strings.

---

### 3. What does `compareTo()` return?

- `0` → Equal
- Negative → Current String comes before the other
- Positive → Current String comes after the other

---

### 4. What is lexicographical comparison?

It is dictionary-style comparison where characters are compared one by one using their Unicode values.

---

### 5. Is `compareTo()` case-sensitive?

Yes.

Use `compareToIgnoreCase()` if you want to ignore case.

---

# Common Mistakes

### Mistake 1

```
String s1 = new String("Java");
String s2 = new String("Java");

System.out.println(s1 == s2);
```

Expecting `true`.

Actual Output

```
false
```

---

### Mistake 2

Using `==` to compare user input.

```
if (username == "admin")
```

Incorrect.

Use

```
if (username.equals("admin"))
```

---

### Mistake 3

Thinking `compareTo()` returns only `-1`, `0`, or `1`.

It returns the **difference based on the first differing characters** (or the length difference if one string is a prefix of the other), so values like `-32`, `15`, etc., are possible.

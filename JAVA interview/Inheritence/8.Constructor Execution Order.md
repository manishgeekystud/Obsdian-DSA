# Constructor Execution Order in Java 

Constructor execution order is a **very common Java interview topic**, especially for **2–8 years experienced developers**. Interviewers often combine it with **inheritance**, **`super()`**, **`this()`**, and **object creation**.

---

# What is Constructor Execution Order?

When an object of a child class is created, **constructors are executed from the top of the inheritance hierarchy to the bottom**.

In simple words:

```
Parent Constructor

↓

Child Constructor
```

**Rule:**

> **A parent constructor always executes before the child constructor.**

---

# Why?

A child class inherits all members of its parent.

Before creating the child object, Java must initialize the parent part of the object.

Therefore,

```
Parent Initialization

↓

Child Initialization
```

---

# Example 1

```
class Animal {

    Animal() {
        System.out.println("Animal Constructor");
    }
}

class Dog extends Animal {

    Dog() {
        System.out.println("Dog Constructor");
    }
}

public class Main {

    public static void main(String[] args) {

        Dog d = new Dog();
    }
}
```

---

## Output

```
Animal Constructor
Dog Constructor
```

When

```

```

```
↓

↓

Initialize Dog Part

↓

Return Object Reference
```

# How JVM Executes It

Suppose

```
Dog d = new Dog();
```

Internally Java behaves like this

```
Dog() {

    super();          // Inserted automatically

    System.out.println("Dog Constructor");
}
```

So actual execution becomes

```
Dog()

↓

super()

↓

Animal()

↓

Return to Dog()

↓

Dog Constructor
```

# Constructor Chaining

Constructor chaining means

One constructor calls another constructor.

Two types

### 1. Using `this()`

Calls another constructor in the same class.

```
class Student {

    Student() {

        this(100);
    }

    Student(int id) {

        System.out.println(id);
    }
}
```

Output

```
100
```

---

### 2. Using `super()`

Calls parent constructor.

```
class Parent {

    Parent() {

        System.out.println("Parent");
    }
}

class Child extends Parent {

    Child() {

        super();

        System.out.println("Child");
    }
}
```

Output

```
Parent

Child
```

---

# `this()` vs `super()`

|Feature|`this()`|`super()`|
|---|---|---|
|Calls|Another constructor in same class|Parent constructor|
|Used for|Constructor chaining|Inheritance|
|First statement?|Yes|Yes|
|Can both appear together?|No|No|

---

# Important Rule

Constructor must begin with

```
this();
```

OR

```
super();
```

Never both.

Wrong

```
Dog() {

    this();

    super();
}
```

Compile-time Error

# Common Mistakes

### Mistake 1

Thinking child constructor executes first.

Wrong.

Parent constructor always executes first.

---

### Mistake 2

Calling `super()` after another statement.

Wrong

```
Dog() {

    System.out.println("Hello");

    super();
}
```

Compile-time Error

Correct

```
Dog() {

    super();

    System.out.println("Hello");
}
```

---

### Mistake 3

Using both `this()` and `super()`.

Wrong

```
Dog() {

    this();

    super();
}
```

Compile-time Error.

---

### Mistake 4

Forgetting `super(parameter)` when the parent has no no-argument constructor.

# Frequently Asked Interview Questions

### 1. Why does the parent constructor execute first?

Because the parent part of the object must be initialized before the child part. A child object contains all the inherited state from its parent.

---

### 2. Does Java automatically call `super()`?

Yes. If you don't explicitly write `super(...)` or `this(...)`, the compiler inserts a no-argument `super()` as the first statement of the constructor.

---

### 3. Can a constructor be inherited?

No. Constructors are **not inherited**. They are executed as part of object creation through constructor chaining.

---

### 4. Can we call `super()` anywhere in the constructor?

No. It must be the **first statement**.

---

### 5. What happens if the parent has only a parameterized constructor?

The child must explicitly call it using `super(arguments)`. Otherwise, compilation fails because the compiler-generated `super()` cannot find a matching no-argument constructor.

---

# Interview Answer (2 Minutes)

> When an object of a child class is created, Java executes constructors from the top of the inheritance hierarchy to the bottom. The parent constructor always runs before the child constructor because the parent portion of the object must be initialized first. If we don't explicitly call a parent constructor, the Java compiler automatically inserts `super()` as the first statement, provided the parent has a no-argument constructor. If the parent only has parameterized constructors, the child must explicitly call one using `super(arguments)`. During object creation, the overall order is: **parent static block → child static block → parent instance block → parent constructor → child instance block → child constructor**. This constructor chaining ensures proper initialization of the entire object.

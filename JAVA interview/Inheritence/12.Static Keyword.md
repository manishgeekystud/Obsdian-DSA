# Static Keyword in Java 
The `static` keyword is one of the **most important Core Java interview topics**. It is asked in almost every Java interview, from freshers to **5–8 years experienced developers**.

Interviewers commonly ask:

- What is `static`?
- Why is `main()` static?
- Can a static method access non-static members?
- Can constructors be static?
- Can we override static methods?
- Difference between static and instance members.

---

# What is `static`?

The `static` keyword means the member belongs to the **class**, **not to individual objects**.

There is **only one copy** of a static member, shared by all objects.

---

# Where can `static` be used?

|Member|Can be Static?|
|---|---|
|Variable|✅ Yes|
|Method|✅ Yes|
|Block|✅ Yes|
|Nested Class|✅ Yes (only nested classes)|
|Constructor|❌ No|
|Local Variable|❌ No|
|Top-level Class|❌ No|

---

# Static Variable (Class Variable)

A static variable belongs to the class, so only **one copy** exists regardless of how many objects are created.

## Example

```
class Student {

    static String college = "ABC College";

    int id;
    String name;

    Student(int id, String name) {
        this.id = id;
        this.name = name;
    }
}
```

```
Student s1 = new Student(1, "John");
Student s2 = new Student(2, "Alice");

System.out.println(s1.college);
System.out.println(s2.college);
```

### Output

```
ABC College
ABC College
```

---

## Memory Diagram

```
                 Method Area

        +-------------------------+
        | Student.college = "ABC" |
        +-------------------------+

                  ▲
                  │ Shared

         Heap

+-------------------+    +-------------------+
| Student Object 1  |    | Student Object 2  |
| id = 1            |    | id = 2            |
| name = John       |    | name = Alice      |
+-------------------+    +-------------------+
```

Only **one** copy of `college` exists.

# Static Method

A static method belongs to the class.

It can be called without creating an object.

## Example

```
class MathUtil {

    static int square(int x) {
        return x * x;
    }
}
```

```
System.out.println(MathUtil.square(5));
```

Output

```
25
```

---

# Calling Static Methods

Preferred

```
MathUtil.square(5);
```

Allowed but discouraged

```
MathUtil obj = new MathUtil();

obj.square(5);
```

The method still belongs to the class.

# Why Can't a Static Method Access Instance Variables?

Example

```
class Test {

    int x = 10;

    static void show() {

        System.out.println(x);
    }
}
```

Compile-time error.

---

## Why?

A static method belongs to the class.

Instance variables belong to objects.

When no object exists, which `x` should Java use?

Example

```
Test t1 = new Test();

Test t2 = new Test();
```

```
t1.x = 10

t2.x = 20
```

If `show()` is called like this

```
Test.show();
```

There is **no object** to decide whether to use `t1.x` or `t2.x`.

Hence the compiler prevents direct access.

---

# Static Method Can Access

✅ Static variables

```
static int count = 10;
```

✅ Other static methods

```
static void display() { }
```

---

# Static Method Cannot Access

❌ Instance variables

❌ Instance methods

unless an object is created.

Example

```
class Test {

    int x = 10;

    static void show() {

        Test t = new Test();

        System.out.println(t.x);
    }
}
```

---

# Why is `main()` Static?

```
public static void main(String[] args)
```

Reasons:

1. JVM calls `main()` without creating an object.
2. The program must start before any object exists.

If `main()` were non-static:

```
class Test {

    public void main(String[] args) { }
}
```

The JVM would need an object first, but it doesn't know how to create one.

---

# Static Block

A static block executes **once**, when the class is loaded into memory.

## Example

```
class Test {

    static {

        System.out.println("Static Block");
    }

    public static void main(String[] args) {

        System.out.println("Main");
    }
}
```

Output

```
Static Block
Main
```

---

# Static Block Uses

- Initialize static variables
- Load configuration
- Register drivers
- Perform one-time setup

---

# Multiple Static Blocks

```
class Test {

    static {

        System.out.println("Block 1");
    }

    static {

        System.out.println("Block 2");
    }

    public static void main(String[] args) {

        System.out.println("Main");
    }
}
```

Output

```
Block 1
Block 2
Main
```

Executed in declaration order.

# Static Variable Initialization Order

```
class Test {

    static int x = 10;

    static {

        x = 20;
    }
}
```

Final value

```
20
```

# Static Nested Class

Only **nested classes** can be static.

```
class Outer {

    static class Inner {

        void show() {

            System.out.println("Inner");
        }
    }
}
```

Usage

```
Outer.Inner obj = new Outer.Inner();

obj.show();
```

---

# Can Constructors Be Static?

No.

```
static Test() { }
```

Compile-time error.

Why?

Constructors initialize objects.

Static belongs to the class.

---

# Can Local Variables Be Static?

No.

```
void show() {

    static int x = 10;
}
```

Compile-time error.

---

# Can Top-Level Classes Be Static?

No.

```
static class Test { }
```

Compile-time error.

Only nested classes may be static.

---

# Static vs Instance Members

|Feature|Static|Instance|
|---|---|---|
|Belongs To|Class|Object|
|Memory|One copy|One per object|
|Access|`ClassName.member`|Object reference|
|Requires Object|No|Yes|
|Loaded|Class loading|Object creation|

---

# Static vs Final

|Static|Final|
|---|---|
|One copy for the class|Cannot be reassigned/overridden/inherited (depending on usage)|
|Shared across objects|Restricts modification|
|Belongs to class|Can apply to variables, methods, classes|

Often used together:

```
public static final double PI = 3.14159;
```

---

# Can Static Methods Be Overridden?

No.

They are **hidden**, not overridden.

```
class Parent {

    static void show() {

        System.out.println("Parent");
    }
}

class Child extends Parent {

    static void show() {

        System.out.println("Child");
    }
}
```

```
Parent p = new Child();

p.show();
```

Output

```
Parent
```

Reason:

Static methods are resolved using the **reference type** (compile-time), not the object type.

# Common Mistakes

### Mistake 1

Trying to access instance variables directly inside a static method.

```
static void show() {

    System.out.println(x);
}
```

Compile-time error.

---

### Mistake 2

Thinking each object gets its own static variable.

Wrong.

There is only **one shared copy**.

---

### Mistake 3

Calling static methods using objects.

```
obj.show();
```

Allowed, but poor practice.

Prefer

```
ClassName.show();
```

---

### Mistake 4

Thinking static methods are polymorphic.

They are not.

Static methods are hidden, not overridden.

# Frequently Asked Interview Questions

### 1. Why is `main()` static?

Because the JVM invokes it without creating an object.

---

### 2. Why can't a static method use `this`?

`this` refers to the current object.

Static methods execute without any object, so `this` does not exist.

---

### 3. Can a static method call a non-static method?

Not directly.

It must first create (or receive) an object.

```
Test t = new Test();

t.display();
```

---

### 4. Can an instance method access static members?

Yes.

Instance methods can access both static and instance members.

---

### 5. Can we overload static methods?

Yes.

```
static void show() { }

static void show(int x) { }
```

This is method overloading.

---

### 6. Can an interface have static methods?

Yes (Java 8+).

```
interface A {

    static void display() {

        System.out.println("Hello");
    }
}
```

Call using

```
A.display();
```

# 1. Field Hiding

## Definition

**Field Hiding** occurs when a child class declares a variable with the **same name** as a variable in the parent class.

The child variable **hides** the parent variable.

---

## Example

```java
class Animal {

    String name = "Animal";
}

class Dog extends Animal {

    String name = "Dog";
}

public class Main {

    public static void main(String[] args) {

        Dog d = new Dog();

        System.out.println(d.name);
    }
}
```

### Output

```
Dog
```

---

# Access Parent Field

Use

```
super.name
```

Example

```java
class Animal {

    String name = "Animal";
}

class Dog extends Animal {

    String name = "Dog";

    void print() {

        System.out.println(name);

        System.out.println(super.name);
    }
}
```

Output

```
Dog
Animal
```

---

# Memory Diagram

```
Dog Object

+-----------------------+

Animal.name = "Animal"

Dog.name    = "Dog"

+-----------------------+
```

Both variables exist in memory.

The child variable simply **hides** the parent variable.

---

# Upcasting Example

```java
class Animal {

    String name = "Animal";
}

class Dog extends Animal {

    String name = "Dog";
}

public class Main {

    public static void main(String[] args) {

        Animal a = new Dog();

        System.out.println(a.name);
    }
}
```

### Output

```
Animal
```

---

## Why?

==Fields are resolved using the **reference type**, **not** the object type.==

Reference type

```
Animal
```

Therefore

```
Animal.name
```

is accessed.

---

# Rule

Fields do **not** participate in runtime polymorphism.

They are resolved at **compile time**.

---

# Field Hiding Summary

|Reference Type|Object Type|Field Access|
|---|---|---|
|Animal|Dog|Animal field|
|Dog|Dog|Dog field|

# 2. Method Hiding

==Method hiding applies only to **static methods**.==

---

## Definition

Method Hiding occurs when a child class declares a **static method** with the **same signature** as a static method in the parent class.

---

## Example

```java
class Animal {

    static void show() {

        System.out.println("Animal");
    }
}

class Dog extends Animal {

    static void show() {

        System.out.println("Dog");
    }
}
```

---

### Calling

```
Dog.show();
```

Output

```
Dog
```

---

### Upcasting Example

```
Animal a = new Dog();

a.show();
```

Output

```
Animal
```

---

## Why?

==Static methods belong to the **class**, not the object.==

Compiler decides using

```
Reference Type
```

Reference is

```
Animal
```

Hence

```
Animal.show()
```

---

# Static Method Example

```java
class Parent {

    static void display() {

        System.out.println("Parent");
    }
}

class Child extends Parent {

    static void display() {

        System.out.println("Child");
    }
}

public class Main {

    public static void main(String[] args) {

        Parent p = new Child();

        p.display();
    }
}
```

Output

```
Parent
```

---

# Why Isn't This Overriding?

Static methods belong to classes.

They are loaded during class loading.

There is no runtime dispatch.

Hence,

```
Method Hiding
```

not

```
Method Overriding
```

---

# Runtime Polymorphism Comparison

## Instance Method

```
class Animal {

    void speak() {

        System.out.println("Animal");
    }
}

class Dog extends Animal {

    @Override
    void speak() {

        System.out.println("Dog");
    }
}
```

```
Animal a = new Dog();

a.speak();
```

Output

```
Dog
```

==Runtime decides using==

```
Object Type
```

---

## Static Method

```
Animal a = new Dog();

a.show();
```

Output

```
Animal
```

Compile time decides using

```
Reference Type
```

# Method Hiding vs Method Overriding

|Feature|Method Hiding|Method Overriding|
|---|---|---|
|Method Type|Static|Instance|
|Decision|Compile Time|Runtime|
|Polymorphism|No|Yes|
|Uses Object Type|No|Yes|
|Uses Reference Type|Yes|No|

|Feature|Field Hiding|Method Hiding|

|Based On|Reference Type|Reference Type|
|Runtime Polymorphism|No|No|

# Memory View

```
Reference Type : Parent

                │
                ▼

        +----------------------+
        |     Child Object     |
        |----------------------|
        | Parent.x = 10        |
        | Child.x = 20         |
        +----------------------+
```

- **Field access** → uses **reference type** (`Parent.x`)
- **Static method** → uses **reference type** (`Parent.show()`)
- **Instance method** → uses **object type** (`Child.display()`)

# Common Mistakes

### Mistake 1

Thinking fields are overridden.

❌ Wrong

Fields are **hidden**, not overridden.

---

### Mistake 2

Thinking static methods are overridden.

❌ Wrong

Static methods are **hidden**, not overridden.

---

### Mistake 3

Expecting runtime polymorphism for static methods.

```
Parent p = new Child();

p.show();
```

Output

```
Parent
```

Not

```
Child
```

---

### Mistake 4

Using `@Override` on a static method.

```
@Override
static void show() {}
```

Compile-time error because static methods cannot be overridden.

# Interview Questions

### 1. What is Field Hiding?

Field hiding occurs when a child class declares a field with the same name as a field in the parent class. Both fields exist, and which one is accessed depends on the **reference type**.

---

### 2. What is Method Hiding?

Method hiding occurs when a child class declares a **static method** with the same signature as a static method in the parent class. The method invoked is determined by the **reference type**, not the object type.

---

### 3. Can fields be overridden?

No. Fields cannot be overridden. They can only be hidden.

---

### 4. Can static methods be overridden?

No. Static methods cannot be overridden. They can only be hidden.

---

### 5. Why doesn't runtime polymorphism work for static methods?

Because static methods belong to the **class**, not the object. They are resolved by the compiler using the **reference type**, so dynamic method dispatch does not apply.

# Final Keyword in Java 

The `final` keyword is one of the **most frequently asked Core Java interview topics**. Interviewers often ask:

- What is `final`?
- Where can it be used?
- Difference between `final`, `finally`, and `finalize()`
- Can a `final` object be modified?
- Can constructors or abstract methods be `final`?

---

# What is `final`?

The `final` keyword is a **non-access modifier** used to **restrict modification**.

Depending on where it is used:

|Used With|Meaning|
|---|---|
|Variable|Value cannot be reassigned|
|Method|Cannot be overridden|
|Class|Cannot be inherited|

---

# 1. Final Variable

A `final` variable can be assigned **only once**.

## Example

```
final int x = 10;

x = 20;   // Compile-time Error
```

Output

```
Cannot assign a value to final variable 'x'
```

---

## Memory Diagram

```
Stack

+------------+

x = 10

+------------+

Reassignment ❌ Not Allowed
```

---

# Blank Final Variable

A blank final variable is declared without initialization.

It **must** be initialized before the constructor finishes.

```
class Student {

    final int id;

    Student(int id) {
        this.id = id;
    }
}
```

Every object can have a different value.

```
Student s1 = new Student(101);

Student s2 = new Student(102);
```

---

# Final Local Variable

```
void test() {

    final int x = 100;

    System.out.println(x);
}
```

Cannot change

```
x = 200;
```

Compile-time error.

---

# Final Reference Variable

This is one of the most asked interview questions.

```
final ArrayList<Integer> list = new ArrayList<>();

list.add(10);

list.add(20);
```

Works perfectly.

Why?

Because the reference is final.

The object is **not** final.

---

## Allowed

```
list.add(100);

list.remove(0);
```

---

## Not Allowed

```
list = new ArrayList<>();
```

Compile-time error.

---

## Memory Diagram

```
Stack

list

 │

 ▼

Heap

+--------------------+

10

20

+--------------------+
```

You cannot change the arrow (reference).

You **can** modify the object.

---

# Final Method

A final method **cannot be overridden**.

```
class Animal {

    final void eat() {

        System.out.println("Eating");
    }
}

class Dog extends Animal {

    void eat() { }   // Compile-time Error
}
```

Output

```
Cannot override final method
```

---

## Why Use Final Methods?

To prevent subclasses from changing important behavior.

Examples:

- Security logic
- Validation logic
- Framework methods

---

# Final Class

A final class cannot be inherited.

```
final class Animal {

}
```

```
class Dog extends Animal {

}
```

Compile-time error.

---

## Real Examples

Some well-known final classes are:

- `String`
- `Integer`
- `Long`
- `Short`
- `Byte`
- `Character`

These classes are immutable and should not be subclassed.

---

# Why is `String` Final?

Reasons include:

- Immutability
- Security
- Thread safety
- Reliable hashing
- Safe use as a `HashMap` key

---

# Final Parameter

```
void display(final int x) {

    System.out.println(x);
}
```

Cannot do

```
x = 20;
```

Compile-time error.

---

# Final with Objects

```
class Student {

    int id;
}
```

```
final Student s = new Student();

s.id = 100;
```

Allowed.

---

But

```
s = new Student();
```

Not allowed.

---

# Final and Constructors

Can constructors be final?

No.

```
final Student() {

}
```

Compile-time error.

Why?

Constructors are never inherited, so overriding is impossible.

Making them final has no meaning.

---

# Final and Abstract

Can a method be both abstract and final?

```
abstract final void test();
```

No.

Compile-time error.

Why?

- `abstract` means subclasses **must override**.
- `final` means subclasses **cannot override**.

These are contradictory.

---

# Final and Static

Allowed.

```
static final double PI = 3.14159;
```

Commonly used for constants.

---

# Constants in Java

Convention:

```
public static final int MAX_SIZE = 100;
```

Why?

- `static` → One copy for the class
- `final` → Cannot change
- Uppercase naming convention

---

# Final vs Finally vs Finalize()

|Feature|`final`|`finally`|`finalize()`|
|---|---|---|---|
|Type|Keyword|Block|Method|
|Purpose|Restrict changes|Always execute cleanup code|Legacy garbage collection callback|
|Used With|Class, Method, Variable|`try-catch`|`Object` class|
|Interview Status|Very common|Very common|Mostly historical (deprecated)|

> **Note:** `finalize()` is deprecated and should not be relied upon for resource cleanup.

# Common Interview Questions

## 1. Can a final object be modified?

Yes.

Example

```
final ArrayList<Integer> list = new ArrayList<>();

list.add(10);
```

Allowed.

Reason:

The object changes.

The reference does not.

---

## 2. Can final variables be initialized later?

Yes.

Blank final variables can be initialized in the constructor.

```
final int id;

Student(int id) {

    this.id = id;
}
```

---

## 3. Can a constructor be final?

No.

Constructors cannot be inherited.

---

## 4. Can an abstract method be final?

No.

They have opposite purposes.

---

## 5. Can we overload a final method?

Yes.

Only overriding is prohibited.

```
class Test {

    final void show() {

    }

    void show(int x) {

    }
}
```

Perfectly valid.

---

## 6. Can a final method be inherited?

Yes.

It can be inherited.

It just cannot be overridden.

---

## 7. Can a final class have methods?

Yes.

```
final class A {

    void show() {

    }
}
```

Valid.

It simply cannot be extended.

---

# Common Mistakes

### Mistake 1

Thinking final objects are immutable.

Wrong.

Only the reference is fixed.

The object's state may still change unless the class itself is immutable.

---

### Mistake 2

Thinking final methods cannot be inherited.

Wrong.

They are inherited.

They just cannot be overridden.

---

### Mistake 3

Confusing final with finally.

- `final` → keyword
- `finally` → exception handling block
- `finalize()` → deprecated cleanup method

---

### Mistake 4

Trying to extend a final class.

```
class B extends String {

}
```

Compile-time error.

---

# Summary Table

|`final` Used On|Effect|
|---|---|
|Variable|Cannot be reassigned|
|Reference Variable|Reference cannot change; object may change|
|Method|Cannot be overridden|
|Class|Cannot be inherited|
|Parameter|Cannot be reassigned inside the method|
|`static final`|Constant|

# Memory Trick

Remember the phrase:

> **"Final means you cannot change the relationship."**

- **Final variable** → Can't change the value/reference.
- **Final method** → Can't change the implementation through overriding.
- **Final class** → Can't change the inheritance hierarchy.

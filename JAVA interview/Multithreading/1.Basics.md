# 1. What is a Process?

## Definition

A **Process** is an independent program that is currently running.

It has its **own memory**, resources, and execution environment.

Whenever you start an application, the Operating System creates a new process.

Examples:

- Chrome Browser
- VS Code
- IntelliJ IDEA
- Spotify

Each of these runs as a separate process.

---

## Process Contains

- Program Code
- Heap Memory
- Stack Memory
- Registers
- Program Counter
- Open Files
- Threads

Every process contains **at least one thread** (called the Main Thread).

---

## Example

When you open IntelliJ:

```
OS
 │
 ├── IntelliJ Process
 │      │
 │      ├── Main Thread
 │      ├── UI Thread
 │      ├── Background Thread
 │      └── GC Thread
```

---

# 2. What is a Thread?

## Definition

A **Thread** is the smallest unit of execution inside a process.

It performs the actual work.

A process can have one or more threads.

---

## Example

Chrome Browser Process

```
Chrome Process

│

├── UI Thread
├── Rendering Thread
├── Network Thread
├── Audio Thread
├── GPU Thread
```

All belong to the same process.

---

## Memory Sharing

Threads share

- Heap
- Method Area
- Files

But every thread has its own

- Stack
- Program Counter
- Registers

---

### Diagram

```
Process

        Shared

+----------------------+
| Heap                 |
+----------------------+
| Method Area          |
+----------------------+

      /      |      \

 Thread1  Thread2 Thread3

 Stack     Stack    Stack
```

---

## Java Example

```
class MyThread extends Thread {

    public void run() {
        System.out.println("Thread Running");
    }
}

public class Demo {

    public static void main(String[] args) {

        MyThread t = new MyThread();

        t.start();
    }
}
```

Output

```
Thread Running
```

---

## Interview Definition

> A Thread is the smallest execution unit inside a process. Multiple threads share the same process resources while executing independently.

## Single Thread

Only one execution path.

```

↓

Task1

↓

Task2

↓

Task3
```

Everything waits.

---

### Example

ATM Machine

One customer at a time.

---

## Multi Thread

Multiple tasks execute concurrently.

```
Task1

Task2

Task3

Task4
```

---

### Example

Browser

- Download
- Play music
- Render page
- Accept user clicks

Everything happens together.

---

## Java Example

Single Thread

```
System.out.println("Task1");

System.out.println("Task2");

System.out.println("Task3");
```

Sequential execution.

---

Multi Thread

```
Thread t1 = new Thread(() ->
        System.out.println("Task1"));

Thread t2 = new Thread(() ->
        System.out.println("Task2"));

t1.start();
t2.start();
```

Order is unpredictable.

## Comparison

|Single Thread|Multi Thread|
|---|---|

# 7. Disadvantages of Multithreading

## 1. Race Condition

Two threads modify same data.

Example

```
Balance = 1000

Thread1 Withdraw

Thread2 Deposit

Wrong Balance Possible
```

---

## 2. Deadlock

Two threads wait forever.

```
Thread1

Lock A

Waiting Lock B

----------------

Thread2

Lock B

Waiting Lock A
```

Neither proceeds.

---

## 3. Starvation

Low priority thread never gets CPU.

---

## 4. Livelock

Threads keep responding to each other but make no progress.

---

## 5. Debugging Difficult

Execution order changes every run.

---

## 6. Context Switching Overhead

Frequent switching between threads can reduce performance if there are too many threads.

# 8. User Thread vs Daemon Thread

Java threads are of two types:

1. User Thread
2. Daemon Thread

---

# User Thread

User threads perform the application's primary work.

Examples:

- Main Thread
- Request Processing Thread
- Business Logic Thread

The JVM waits for all user threads to finish before exiting.

---

## Example

```
public class Demo {
    public static void main(String[] args) {

        Thread t = new Thread(() -> {
            while (true) {
                System.out.println("Working...");
            }
        });

        t.start();
    }
}
```

The JVM keeps running because a user thread is alive.

---

# Daemon Thread

Daemon threads support background tasks.

Examples:

- Garbage Collector (GC)
- Monitoring
- Logging
- Cleanup

When all user threads finish, the JVM exits and automatically stops daemon threads.

---

## Example

```
public class Demo {

    public static void main(String[] args) {

        Thread t = new Thread(() -> {
            while (true) {
                System.out.println("Daemon Running");
            }
        });

        t.setDaemon(true);   // Must be called before start()
        t.start();

        System.out.println("Main Ends");
    }
}
```

Possible Output

```
Main Ends
```

The daemon thread may stop immediately because no user threads remain.

> **Important:** Calling `setDaemon(true)` **after** `start()` throws an `IllegalThreadStateException`.

---

## Comparison

|Feature|User Thread|Daemon Thread|
|---|---|---|
|Purpose|Application work|Background support work|
|JVM Waits?|Yes|No|
|Examples|Main thread, worker thread|Garbage Collector, monitoring|
|Lifetime|Until work completes|Ends when all user threads end|
|Created By|Developer/JVM|Developer/JVM|

# Frequently Asked Interview Questions

### 1. Can a process exist without a thread?

**No.** Every process has at least one thread (the main thread).

---

### 2. Can multiple threads share memory?

**Yes.** Threads within the same process share the heap and method area but have separate stacks.

---

### 3. Which is faster: Process or Thread creation?

**Thread creation** is faster because threads share process resources.

---

### 4. Why is multithreading used?

To improve responsiveness, CPU utilization, throughput, and overall application performance.

---

### 5. Can a daemon thread keep the JVM alive?

**No.** The JVM exits when no user threads are running, even if daemon threads are still active.

---

### 6. Can we convert a user thread into a daemon thread?

**Yes**, by calling `setDaemon(true)` **before** invoking `start()`.

---

### 7. Give examples of daemon threads.

- Garbage Collector
- Finalizer (legacy)
- Monitoring threads
- Background cleanup tasks

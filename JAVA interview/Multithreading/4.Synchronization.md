# Synchronization (⭐⭐⭐⭐⭐)

# What is Synchronization?

## Definition

**Synchronization** is a mechanism in Java that ensures **only one thread at a time can access a shared resource (critical section)**, preventing inconsistent data and race conditions.

In simple words,

> **Synchronization controls concurrent access to shared resources by multiple threads to maintain data consistency and thread safety.**

---

## Why Synchronization is Needed?

Suppose two threads are updating the same bank account simultaneously.

Without synchronization:

```
Balance = 1000

Thread A Withdraw 500

Thread B Deposit 200
```

Both threads access the same variable at the same time.

Possible result:

```
Expected Balance = 700

Actual Balance = 500
```

Wrong answer due to **Race Condition**.

---

## Memory Diagram (Without Synchronization)

```
                Heap Memory
          -----------------------
          | Balance = 1000      |
          -----------------------
             ▲              ▲
             |              |
        Thread A       Thread B
          Read            Read
          1000            1000
             |              |
      Write 500      Write 1200
             \            /
          Last Write Wins
```

Both threads read the same old value and overwrite each other's changes.

---

## Memory Diagram (With Synchronization)

```
                Heap Memory
          -----------------------
          | Balance = 1000      |
          -----------------------
                   ▲
                   |
           Monitor Lock
              /      \
             /        \
       Thread A     Thread B
      (Inside)      Waiting
```

Only one thread executes the critical section.

---

# What is Synchronization Actually Protecting?

Synchronization protects the **Critical Section**.

## Critical Section

A section of code where shared data is accessed or modified.

Example:

```
balance = balance + amount;
```

This statement looks simple but internally it performs:

```
Read balance

↓

Add amount

↓

Write balance
```

If another thread modifies `balance` during these steps, data becomes inconsistent.

---

# Interview Definition

> Synchronization ensures that only one thread executes the critical section at a time by acquiring a lock before entering the synchronized code.

---

# Why Synchronization?

Synchronization is used to:

- Prevent race conditions.
- Ensure data consistency.
- Protect shared resources.
- Achieve thread safety.
- Coordinate multiple threads.

---

```
class Counter {

    int count = 0;

    void increment() {

    }
}
```

Suppose:

```
Thread A

count++

Thread B

count++
```

Expected:

```

```

Possible Output:

```
1
```

---

## Why?

Because

```
count++
```

is internally

```
Read

↓

Increment

↓

```

Three operations.

```

    int count = 0;

    }

```

Now

```

↓

Lock

↓

Increment

↓

Unlock

↓

Thread B
```

```

```

# Intrinsic Lock (Monitor Lock)

## Definition

Every Java object has an **intrinsic lock**, also called a **monitor lock**.

Whenever a thread enters a synchronized method or block, it must first acquire the object's monitor lock.

Only one thread can own the monitor at a time.

---

## Memory Diagram

```
          Object

    ------------------

      Data Members

      count = 10

    ------------------

      Monitor Lock

    ------------------
```

Every object automatically has one monitor.

---

## Interview Point

**Intrinsic Lock**, **Monitor Lock**, and **Object Monitor** all refer to the same concept.

---

# Object Lock

An **object lock** belongs to a specific object instance.

Each object has its own lock.

Example:

```
Counter c1 = new Counter();

Counter c2 = new Counter();
```

Memory:

```
Counter c1

Monitor Lock A

----------------

Counter c2

Monitor Lock B
```

Both objects can be synchronized independently.

---

# Example

```
class Counter {

    synchronized void print() {

    }

}
```

Calling

```
c1.print();
```

locks

```
c1
```

Calling

```
c2.print();
```

locks

```
c2
```

Both can execute simultaneously because they use different locks.

---

# Class Lock

Static synchronized methods lock the **Class object**, not individual instances.

Example

```
class Counter {

    static synchronized void display() {

    }

}
```

Lock acquired:

```
Counter.class
```

---

## Memory Diagram

```
JVM

↓

Counter.class

↓

Class Monitor Lock
```

Only one thread can execute any static synchronized method of that class at a time.

---

# Object Lock vs Class Lock

|Object Lock|Class Lock|
|---|---|
|Instance level|Class level|
|Locks object|Locks `Class` object|
|One lock per object|One lock per class|
|`synchronized` instance methods|`static synchronized` methods|

---

# Synchronized Method

A synchronized method acquires the object's monitor lock before execution.

Example

```
class Printer {

    synchronized void print() {

        System.out.println("Printing");

    }

}
```

Equivalent to:

```
void print() {

    synchronized(this){

        System.out.println("Printing");

    }

}
```

---

## Interview Point

A synchronized instance method is internally equivalent to synchronizing on `this`.

---

# Synchronized Block

Instead of locking the whole method, synchronize only the critical section.

Example

```
void print() {

    // Non-critical code

    synchronized(this){

        System.out.println("Critical Section");

    }

    // Non-critical code

}
```

---

## Why Prefer Synchronized Block?

Less code is locked.

Advantages:

- Better performance.
- Less waiting.
- More concurrency.

---

# Memory Diagram

```
Method

↓

Normal Code

↓

Lock Acquired

↓

Critical Section

↓

Lock Released

↓

Remaining Code
```

---

# Static Synchronization

Used for static methods.

Example

```
class Demo {

    static synchronized void display() {

    }

}
```

Internally equivalent to

```
synchronized(Demo.class){

}
```

---

# Nested Synchronization

A synchronized block inside another synchronized block.

Example

```
synchronized(lock1){

    synchronized(lock2){

        // Critical Section

    }

}
```

---

## Risk

Nested synchronization may lead to **Deadlock** if threads acquire locks in different orders.

Example

```
Thread1

Lock A

↓

Waiting Lock B

-------------------

Thread2

Lock B

↓

Waiting Lock A
```

Neither thread proceeds.

---

# Reentrant Synchronization ⭐⭐⭐⭐⭐

One of the most common interview questions.

---

## Definition

A thread holding a lock can acquire the **same lock again** without getting blocked.

Java's intrinsic locks are **reentrant**.

---

## Example

```
class Demo {

    synchronized void methodA() {

        methodB();

    }

    synchronized void methodB() {

        System.out.println("Inside B");

    }

}
```

Flow:

```
Thread

↓

methodA()

↓

Lock Acquired

↓

Calls methodB()

↓

Same Lock Again

↓

Allowed
```

No deadlock occurs because the same thread already owns the lock.

---

## Why Reentrant?

The JVM keeps a **lock count**.

Example:

```
methodA()

Lock Count = 1

↓

methodB()

Lock Count = 2

↓

methodB Ends

Lock Count = 1

↓

methodA Ends

Lock Count = 0

↓

Lock Released
```

The lock is released only when the count reaches zero.

---

# Complete Memory Diagram

```
                Heap

        ------------------

           Counter Object

           count = 10

        ------------------

          Monitor Lock

        ------------------

                ▲
                |
        ------------------
        |                |
     Thread A        Thread B
   Lock Acquired      Waiting
```

After Thread A exits:

```
Thread A Releases Lock
        |
        v
Thread B Acquires Lock
```

# Interview Summary

|Topic|Key Point|
|---|---|
|Synchronization|Allows only one thread to execute the critical section at a time.|
|Why|Prevents race conditions and ensures thread safety.|
|Intrinsic Lock|Every Java object has a built-in monitor lock.|
|Object Lock|Lock associated with a specific object instance.|
|Class Lock|Lock associated with the `Class` object (`static synchronized`).|
|Synchronized Method|Locks the entire method (`this` for instance methods).|
|Synchronized Block|Locks only the required critical section, improving performance.|
|Static Synchronization|Locks `ClassName.class`, shared by all instances.|
|Nested Synchronization|Acquiring one lock inside another; can lead to deadlock if lock ordering differs.|
|Reentrant Synchronization|The same thread can acquire the same lock multiple times; the JVM maintains a lock count.|

# Synchronization Interview Questions (⭐⭐⭐⭐⭐)

---

# 1. What is Synchronization?

### Interview Answer

> Synchronization is a mechanism in Java that ensures only one thread at a time can execute the critical section of code. It prevents multiple threads from simultaneously accessing shared resources, thereby avoiding race conditions and ensuring data consistency.

---

# 2. Why is Synchronization Required?

### Interview Answer

Synchronization is required because multiple threads may access the same shared resource simultaneously.

Without synchronization:

- Race Condition
- Data Corruption
- Lost Updates
- Inconsistent Data

With synchronization:

- Thread Safety
- Data Consistency
- Mutual Exclusion

---

# 3. What is a Critical Section?

### Interview Answer

A critical section is the portion of code that accesses or modifies shared resources.

Example

```
balance = balance + amount;
```

Only one thread should execute this section at a time.

---

# 4. What is an Intrinsic Lock (Monitor Lock)?

### Interview Answer

Every Java object has a built-in lock called an **Intrinsic Lock** or **Monitor Lock**.

Whenever a thread enters a synchronized method or synchronized block, it must first acquire this monitor lock.

Only one thread can own a monitor lock at a time.

---

# 5. Does Every Object Have Its Own Monitor Lock?

### Answer

Yes.

Every object created in Java has its own monitor lock.

Example

```
Employee e1 = new Employee();

Employee e2 = new Employee();
```

Both objects have separate monitor locks.

---

# 6. What is an Object Lock?

### Interview Answer

Object lock is the monitor lock associated with an object instance.

Instance synchronized methods use object locks.

Example

```
synchronized void print() {

}
```

Equivalent to

```
synchronized(this){

}
```

---

# 7. What is a Class Lock?

### Interview Answer

Class lock is associated with the Class object.

It is acquired when executing a static synchronized method.

Example

```
static synchronized void display(){

}
```

Internally

```
synchronized(Employee.class){

}
```

Only one thread can execute any static synchronized method of that class.

---

# 8. Difference Between Object Lock and Class Lock

|Object Lock|Class Lock|
|---|---|
|Instance level|Class level|
|One lock per object|One lock per class|
|Used by instance synchronized methods|Used by static synchronized methods|
|Lock = `this`|Lock = `ClassName.class`|

---

# 9. Can One Thread Execute a Static Synchronized Method While Another Executes an Instance Synchronized Method?

### Answer

Yes.

Because

Instance method uses

```
Object Lock
```

Static method uses

```
Class Lock
```

Different locks.

---

# 10. Difference Between Synchronized Method and Synchronized Block

### Synchronized Method

```
synchronized void print(){

}
```

Entire method is locked.

---

### Synchronized Block

```
void print(){

    synchronized(this){

    }

}
```

Only critical section is locked.

---

# Which is Better?

Synchronized Block.

Reason:

- Better performance
- Smaller critical section
- Less waiting
- Better concurrency

---

# 11. What Happens Internally When a Thread Enters a Synchronized Method?

### Interview Answer

Internally

1. Thread requests monitor lock.
2. JVM checks whether the lock is free.
3. If free → acquires lock.
4. Executes synchronized code.
5. Releases lock after execution.
6. Waiting thread acquires the lock.

---

# 12. What Happens If Another Thread Already Owns the Lock?

### Answer

The second thread enters the

```
BLOCKED
```

state.

It waits until the monitor lock is released.

---

# 13. Can Two Threads Execute the Same Synchronized Method Simultaneously?

### Same Object

No.

Only one thread gets the object lock.

---

### Different Objects

Yes.

Different objects have different monitor locks.

---

# 14. What is Static Synchronization?

### Interview Answer

Static synchronization synchronizes static methods.

It locks the Class object rather than individual objects.

Example

```
static synchronized void show(){

}
```

Equivalent to

```
synchronized(Demo.class){

}
```

---

# 15. What is Nested Synchronization?

### Interview Answer

Nested synchronization means acquiring one synchronized lock inside another synchronized lock.

Example

```
synchronized(lock1){

    synchronized(lock2){

    }

}
```

---

# 16. What is the Problem with Nested Synchronization?

### Answer

Nested synchronization may lead to

```
Deadlock
```

If two threads acquire locks in different order.

---

# 17. What is Reentrant Synchronization?

### Interview Answer

Reentrant synchronization means a thread already holding a lock can acquire the same lock multiple times without blocking itself.

Example

```
synchronized void methodA(){

    methodB();

}

synchronized void methodB(){

}
```

The thread already owns the lock.

No deadlock occurs.

---

# 18. How Does Java Implement Reentrant Synchronization?

### Answer

The JVM maintains a

```
Lock Counter
```

Example

```
methodA()

↓

Lock Count = 1

↓

methodB()

↓

Lock Count = 2

↓

methodB Ends

↓

Lock Count = 1

↓

methodA Ends

↓

Lock Count = 0

↓

Lock Released
```

---

# 19. Can Constructors Be Synchronized?

### Answer

No.

Constructors cannot be declared synchronized because the object is still being created and is not yet shared between threads.

---

# 20. Can Static Blocks Be Synchronized?

### Answer

No.

Static initialization blocks cannot be declared synchronized.

They execute only once during class loading.

---

# 21. What Happens If an Exception Occurs Inside a Synchronized Block?

### Interview Answer

When the thread exits the synchronized block due to an exception, the JVM automatically releases the monitor lock.

Other waiting threads can then acquire the lock.

---

# 22. Does Synchronization Guarantee Thread Safety?

### Interview Answer

Synchronization provides mutual exclusion and memory visibility for the synchronized code, but thread safety also depends on the overall design. If shared data is accessed outside synchronized code, the application may still not be thread-safe.

---

# 23. Why Is Synchronization Slow?

### Interview Answer

Synchronization introduces overhead because:

- Threads compete for locks.
- Threads may become BLOCKED.
- Context switching increases.
- Lock acquisition and release take time.

Modern JVMs optimize many synchronization scenarios, but excessive locking can still reduce performance.

---

# 24. Why Is Synchronized Block Preferred Over Synchronized Method?

### Interview Answer

Because only the critical section is locked.

Advantages:

- Less lock contention
- Better CPU utilization
- Better scalability
- Better performance

---

# 25. Can Synchronization Prevent Deadlock?

### Answer

No.

Synchronization itself can actually **cause deadlocks** if multiple locks are acquired in inconsistent order.

To avoid deadlocks:

- Acquire locks in a consistent order.
- Minimize nested synchronization.
- Consider higher-level concurrency utilities when appropriate.

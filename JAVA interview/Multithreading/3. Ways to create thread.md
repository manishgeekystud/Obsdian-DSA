# Ways to Create Threads

There are several ways to execute code in a separate thread in Java:

1. Extending `Thread`
2. Implementing `Runnable`
3. Implementing `Callable`
4. Using `ExecutorService`
5. Using Lambda Expressions
6. Using `Future`
7. Using `FutureTask`

---

# 1. Extending Thread Class

## Theory

The simplest way to create a thread is by extending the `Thread` class and overriding the `run()` method.

When `start()` is called, the JVM creates a new thread and invokes `run()` internally.

---

## Example

```
class MyThread extends Thread {

    @Override
    public void run() {
        System.out.println("Thread is running");
    }
}

public class Demo {

    public static void main(String[] args) {

        MyThread t = new MyThread();

        t.start();
    }
}
```

Output

```
Thread is running
```

---

## Advantages

- Very easy to understand.
- Good for learning.

---

## Disadvantages

- Java supports only **single inheritance**.
- If you extend `Thread`, you cannot extend any other class.
- Business logic and thread management become tightly coupled.
- Not preferred in enterprise applications.

---

## Interview Definition

> Extending `Thread` is the simplest way to create a thread, but it is generally avoided because it prevents class inheritance and mixes business logic with thread management.

---

# 2. Implementing Runnable ⭐⭐⭐⭐⭐

## Theory

Instead of extending `Thread`, implement the `Runnable` interface.

`Runnable` contains only one method:

```
void run();
```

A `Thread` object is created by passing the `Runnable` instance.

---

## Example

```java
class MyTask implements Runnable {

    @Override
    public void run() {
        System.out.println("Runnable executing");
    }
}

public class Demo {

    public static void main(String[] args) {

        Thread t = new Thread(new MyTask());

        t.start();
    }
}
```

---

## Advantages

- Supports inheritance from another class.
- Better separation of concerns.
- Reusable task.
- Preferred over extending `Thread`.

---

## Disadvantages

- Cannot return a value.
- Cannot throw checked exceptions directly from `run()`.

---

## Interview Definition

> `Runnable` separates the task from the thread that executes it, making the design more flexible and reusable.

---

# Thread vs Runnable

```
Runnable  ---> Task

Thread ----> Executes Task
```

---

# 3. Using Callable ⭐⭐⭐⭐⭐

## Theory

`Callable` was introduced in Java 5.

Unlike `Runnable`, it:

- Returns a value.
- Can throw checked exceptions.

Method:

```
V call() throws Exception
```

---

## Example

```java
import java.util.concurrent.*;

class MyTask implements Callable<Integer> {

    @Override
    public Integer call() {
        return 100;
    }
}

public class Demo {

    public static void main(String[] args) throws Exception {

        ExecutorService service =
                Executors.newSingleThreadExecutor();

        Future<Integer> future =
                service.submit(new MyTask());

        System.out.println(future.get());

        service.shutdown();
    }
}
```

Output

```
100
```

---

## Advantages

- Returns result.
- Throws checked exceptions.
- Used with thread pools.

---

## Disadvantages

- Requires `ExecutorService`.
- Slightly more complex.

---

# Runnable vs Callable

|Runnable|Callable|
|---|---|
|`run()`|`call()`|
|No return value|Returns value|
|No checked exception|Can throw checked exception|
|Older|Introduced in Java 5|
|Used for simple tasks|Used for computation tasks|

---

# 4. Using ExecutorService ⭐⭐⭐⭐⭐

## Theory

Creating a thread for every task is expensive.

Instead, Java provides **Thread Pools** through `ExecutorService`.

It reuses threads.

---

## Example

```
ExecutorService service =
        Executors.newFixedThreadPool(3);

service.execute(() ->
        System.out.println(Thread.currentThread().getName()));

service.shutdown();
```

---

## Advantages

- Thread reuse.
- Better performance.
- Controls thread count.
- Production-ready.
- Used in Spring Boot and enterprise applications.

---

## Why Thread Pool?

Without pool

```
Task1 -> Thread1

Task2 -> Thread2

Task3 -> Thread3
```

Creates many threads.

With pool

```
Pool

Thread1

Thread2

Thread3

↓

Handles many tasks
```

---

# Interview Definition

> `ExecutorService` manages thread creation, reuse, and lifecycle efficiently through thread pools. It is the preferred approach in production systems.

---

# 5. Lambda Expressions (Java 8)

Since `Runnable` is a functional interface, it can be implemented using a lambda.

---

## Example

```
Thread t = new Thread(() -> {

    System.out.println("Lambda Thread");

});

t.start();
```

---

Instead of

```
new Runnable(){

    public void run(){

    }

}
```

---

## Advantages

- Less code.
- More readable.
- Common in Java 8+.

---

# 6. Future ⭐⭐⭐⭐⭐

## Theory

`Future` represents the result of an asynchronous computation.

It allows you to:

- Get the result later.
- Check if the task is complete.
- Cancel the task.

---

## Example

```
ExecutorService service =
        Executors.newSingleThreadExecutor();

Future<Integer> future =
        service.submit(() -> 500);

System.out.println(future.get());

service.shutdown();
```

Output

```
500
```

---

## Common Methods

```
future.get();

future.isDone();

future.cancel(true);

future.isCancelled();
```

---

## Limitation

`get()` blocks until the task completes.

---

# 7. FutureTask

## Theory

`FutureTask` implements both:

- `Runnable`
- `Future`

It can be executed by a thread and also return a result.

---

## Example

```
Callable<Integer> task = () -> 10;

FutureTask<Integer> futureTask =
        new FutureTask<>(task);

Thread t = new Thread(futureTask);

t.start();

System.out.println(futureTask.get());
```

Output

```
10
```

---

## Advantages

- Can run like a thread.
- Returns result.
- Can be reused with executors.

---

# Complete Comparison

|Feature|Thread|Runnable|Callable|ExecutorService|
|---|---|---|---|---|
|Extend class|Yes|No|No|No|
|Returns value|No|No|Yes|Yes (with Callable)|
|Checked Exception|No|No|Yes|Yes|
|Thread Pool|No|No|Yes|Yes|
|Production Ready|No|Better|Better|Best|
|Preferred|Learning|Good|Better|Best|

---

# Which Approach Do You Prefer and Why? ⭐⭐⭐⭐⭐

This is one of the most common interview questions.

## Sample Interview Answer

> "In enterprise applications, I prefer using **ExecutorService** with **Callable** whenever a task needs to return a result. `ExecutorService` manages a thread pool, reuses threads, reduces the overhead of creating new threads, and provides better scalability and lifecycle management. If the task does not need to return a value, I use `Runnable` with an `ExecutorService`. I generally avoid extending the `Thread` class because it tightly couples the task with the thread and also prevents extending any other class due to Java's single inheritance."

---

# When to Use What?

|Scenario|Recommended Approach|
|---|---|
|Learning multithreading|Extend `Thread`|
|Simple background task|`Runnable`|
|Need a return value|`Callable`|
|Need thread pooling|`ExecutorService`|
|Java 8+ concise syntax|Lambda + `Runnable`/`Callable`|
|Need asynchronous result|`Future`|
|Need both `Runnable` and result handling|`FutureTask`|

---

# Frequently Asked Interview Questions

### 1. Why is `Runnable` preferred over extending `Thread`?

- Supports inheritance from another class.
- Better separation of concerns.
- More reusable and flexible.

---

### 2. What is the difference between `Runnable` and `Callable`?

- `Runnable` does not return a value and cannot throw checked exceptions.
- `Callable` returns a value and can throw checked exceptions.

---

### 3. Why is `ExecutorService` preferred in production?

- Reuses threads through thread pools.
- Improves performance.
- Controls concurrency.
- Simplifies thread lifecycle management.

---

### 4. What is the purpose of `Future`?

It represents the result of an asynchronous computation and allows checking completion, retrieving the result, or cancelling the task.

---

### 5. What is `FutureTask`?

`FutureTask` is a concrete implementation that combines **`Runnable`** and **`Future`**, allowing a task to be executed by a thread while also producing a result.

---

# Interview Summary (30-Second Revision)

- **`Thread`** → Simple, but rarely used in production.
- **`Runnable`** → Preferred for tasks without return values.
- **`Callable`** → Use when a result or checked exception handling is required.
- **`ExecutorService`** → Best choice for enterprise applications because it manages thread pools efficiently.
- **Lambda** → Cleaner syntax for `Runnable` and `Callable`.
- **`Future`** → Represents the result of an asynchronous task.
- **`FutureTask`** → Combines execution (`Runnable`) with result retrieval (`Future`).

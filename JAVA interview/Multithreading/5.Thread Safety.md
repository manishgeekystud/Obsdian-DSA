# 1. What is Thread Safety? ⭐⭐⭐⭐⭐

## Definition

A class or object is **thread-safe** if it behaves correctly when multiple threads access it simultaneously without causing data inconsistency, race conditions, or unexpected behavior.

In simple words:

> **A thread-safe class allows multiple threads to access shared resources safely without corrupting data.**

---

## Why Do We Need Thread Safety?

Suppose two threads update the same bank account.

Without thread safety:

```
Balance = 1000

Thread A Withdraw 500

Thread B Deposit 200
```

Possible Output

```
500
```

Expected

```
700
```

Wrong result due to Race Condition.

---

## Thread Safe vs Not Thread Safe

### Thread Safe

```
Thread A

↓

Shared Object

↓

Correct Data

↑

Thread B
```

---

### Not Thread Safe

```
Thread A

↓

Shared Data

↑

Thread B

↓

Race Condition

↓

Wrong Result
```

---

## Interview Definition

> Thread safety means ensuring that shared resources are accessed correctly by multiple threads through proper synchronization, immutability, atomic operations, or other concurrency techniques.

---

# 2. Stateless Objects ⭐⭐⭐⭐⭐

## Definition

A stateless object does **not store any instance state**.

Every method works only with:

- Local variables
- Method parameters

No shared mutable data.

---

## Example

```
class Calculator {

    int add(int a, int b) {

        return a + b;

    }

}
```

No instance variables.

Multiple threads can safely call:

```
calculator.add(10,20);
```

---

## Why Thread Safe?

Because:

- No shared data.
- Local variables are stored in each thread's own stack.
- Threads never interfere.

---

## Memory Diagram

```
Thread A Stack

a=10

b=20

---------------

Thread B Stack

a=30

b=40
```

Separate stacks.

---

## Advantages

- Naturally thread-safe.
- No synchronization required.
- High performance.

---

## Interview Point

Most **utility classes** are stateless.

Example

```
Math

Collections

Arrays
```

---

# 3. Immutable Objects ⭐⭐⭐⭐⭐

## Definition

An immutable object cannot be modified after creation.

Once created,

Its state never changes.

---

## Example

```
String s = "Java";
```

After

```
s.concat("8");
```

Original String remains unchanged.

---

## Why Thread Safe?

Because

No thread can modify the object.

Only reading occurs.

No synchronization required.

---

## Rules for Immutable Class

- Make class `final`
- Make fields `private final`
- No setters
- Initialize through constructor
- Return defensive copies for mutable fields

---

## Example

```
final class Employee {

    private final int id;

    Employee(int id){

        this.id=id;

    }

    public int getId(){

        return id;

    }

}
```

---

## Memory Diagram

```
Heap

Employee

id =101

(Read Only)
```

Multiple threads only read.

---

## Interview Point

Most common immutable class

```
String
```

---

# 5. Atomic Classes ⭐⭐⭐⭐⭐
# What are Atomic Classes?

## Definition

Atomic Classes are thread-safe classes provided by the **`java.util.concurrent.atomic`** package that perform **atomic (indivisible) operations** on variables without using explicit synchronization.

In simple words:

> **Atomic classes allow multiple threads to update shared variables safely without using synchronized blocks or locks.**

---

# Why Do We Need Atomic Classes?

Suppose multiple threads increment a counter.

Without synchronization:

```
count++;
```

Looks simple, but internally it performs:

```
Read count
     ↓
Increment
     ↓
Write count
```

If two threads execute these steps simultaneously:

```
Initial count = 10

Thread A reads 10
Thread B reads 10

Thread A writes 11
Thread B writes 11

Final count = 11 ❌
Expected = 12
```

This is a **Race Condition**.

---

## Using synchronized

```
synchronized void increment() {
    count++;
}
```

This works but:

- Uses locks
- Threads may block
- Context switching overhead
- Reduced performance

---

## Using AtomicInteger

```
AtomicInteger count = new AtomicInteger(0);

count.incrementAndGet();
```

Safe without explicit synchronization.

---

# What Does "Atomic" Mean?

An **atomic operation** is an operation that:

- Executes completely.
- Cannot be interrupted.
- Appears as a single indivisible step.

Example:

```
incrementAndGet()
```

Either the increment happens completely or not at all.

No intermediate state is visible.

---

# Package

```
java.util.concurrent.atomic
```

---

# Common Atomic Classes

|Class|Purpose|
|---|---|
|`AtomicInteger`|Integer counter|
|`AtomicLong`|Long counter|
|`AtomicBoolean`|Boolean flag|
|`AtomicReference<T>`|Object reference|
|`AtomicIntegerArray`|Integer array|
|`AtomicLongArray`|Long array|
|`AtomicReferenceArray`|Reference array|

---

```
import java.util.concurrent.atomic.AtomicInteger;
```

# 7. Thread Confinement ⭐⭐⭐⭐⭐

## Definition

Thread confinement means an object is accessed by **only one thread**.

Since no sharing exists,

No synchronization is required.

---

## Types

### Method Local Variables

```
void print(){

    int x=10;

}
```

Every thread has its own stack.

Safe.

---

### ThreadLocal

Each thread gets its own copy.

Example

```
ThreadLocal<Integer> local =
ThreadLocal.withInitial(() -> 0);
```

Thread A

```
10
```

Thread B

```
20
```

Different values.

---

## Memory Diagram

```
Thread A

↓

ThreadLocal

↓

100

-------------------

Thread B

↓

ThreadLocal

↓

500
```

---

## Advantages

- No synchronization
- No race conditions
- Better performance

---

|Technique|How It Works|
|---|---|

|Synchronization|One thread at a time|
|Atomic Classes|Lock-free atomic operations (CAS)|
|Concurrent Collections|Thread-safe data structures|
|Thread Confinement|Object confined to one thread|

# Interview Questions ⭐⭐⭐⭐⭐

## 1. What is Thread Safety?

> A class is thread-safe if it behaves correctly when multiple threads access it simultaneously without causing data inconsistency or race conditions.

---

## 2. Which is Better: Stateless or Immutable?

**Both are thread-safe.**

- Stateless → No state at all.
- Immutable → State exists but never changes.

---

## 3. Why are Immutable Objects Thread Safe?

Because their state cannot change after construction, so multiple threads can safely read them without synchronization.

---

## 4. Why are Local Variables Thread Safe?

Because they are stored in each thread's private stack and are never shared with other threads.

---

## 5. What are Atomic Classes?

Atomic classes provide lock-free, thread-safe operations using the **Compare-And-Swap (CAS)** algorithm.

---

## 6. Why is `AtomicInteger` Better Than `synchronized` for Counters?

- No monitor lock.
- Uses CAS.
- Better performance.
- Non-blocking.

---

## 7. Why is `ConcurrentHashMap` Better Than `Hashtable`?

- Higher concurrency.
- Better scalability.
- Less lock contention.
- Better throughput under multi-threaded access.

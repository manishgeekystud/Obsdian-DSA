# What is Thread Lifecycle?

A thread does not execute immediately after creation.

It moves through several states from **creation** until **termination**.

Java defines these states in:

```
java.lang.Thread.State
```

There are **only six official states**.

```
NEW
RUNNABLE
BLOCKED
WAITING
TIMED_WAITING
TERMINATED
```

# 1. NEW State

## Definition

A thread is created but has **not yet started**.

Example

```
Thread t = new Thread();
```

Current State

```
NEW
```

Nothing is executing yet.

---

## Memory View

```
Thread Object Created

Thread t

↓

NEW

(Not scheduled)
```

---

## Example

```
Thread t = new Thread();

System.out.println(t.getState());
```

Output

```
NEW
```

---

## Transition

```
NEW
   |
start()
   |
RUNNABLE
```

---

# 2. RUNNABLE State

## Definition

After calling

```
t.start();
```

the thread enters the **RUNNABLE** state.

This means

- Ready to execute
- Or currently executing

Java **combines Ready + Running** into one state.

---

## Important

Many students think

```
NEW
↓

RUNNABLE

↓

RUNNING
```

This is **wrong** in Java.

Java has **no RUNNING state**.

---

## Example

```
Thread t = new Thread(() -> {

    System.out.println("Running");

});

t.start();
```

Immediately after

```
RUNNABLE
```

---

## Interview Definition

> RUNNABLE means the thread is eligible for CPU execution. It may either be waiting for CPU time or actively executing.

---

# Why RUNNING is NOT an Official Java Thread State ⭐⭐⭐⭐⭐

This is one of the most common interview questions.

---

## Operating System Perspective

The OS distinguishes between:

```
READY

RUNNING
```

Example

```
Ready Queue

Thread1

Thread2

Thread3
```

CPU

```
Thread2 Running
```

---

## Java Perspective

Java does **not expose** these separately.

Instead

```
READY

+

RUNNING

=

RUNNABLE
```

So when

```
thread.getState();
```

returns

```
RUNNABLE
```

the thread may be

- Waiting in Ready Queue
- Executing on CPU

Java doesn't differentiate.

---

## Why?

Because scheduling is handled by the Operating System.

Java doesn't know exactly when the CPU starts executing the thread.

---

## Interview Answer

> Java intentionally combines Ready and Running into the RUNNABLE state because thread scheduling is managed by the operating system, and Java cannot reliably distinguish whether a runnable thread is merely eligible to run or is currently executing.

# WAITING vs TIMED_WAITING

|WAITING|TIMED_WAITING|
|---|---|
|Infinite wait|Fixed duration|
|Needs notification or completion|Wakes automatically after timeout|
|`wait()`|`sleep()`|
|`join()`|`join(timeout)`|
|`park()`|`parkNanos()`|

## Definition

Thread finishes execution.

Cannot restart.

```

```


# JVM Thread Scheduler ⭐⭐⭐⭐⭐

## What is it?

The **JVM Thread Scheduler** decides **which RUNNABLE thread gets CPU time**.

However, it does **not directly execute threads**. The JVM delegates scheduling to the **underlying operating system's scheduler**.

---

## How it Works

Suppose there are three runnable threads:

```
RUNNABLE Queue

Thread A

Thread B

Thread C
```

The OS scheduler may choose:

```
CPU

↓

Thread B
```

Later:

```
CPU

↓

Thread A
```

Then:

```
CPU

↓

Thread C
```

The selection order is **not guaranteed**.

---

## Scheduler Characteristics

- Chooses one RUNNABLE thread at a time (per CPU core).
- Delegates actual scheduling to the operating system.
- Uses time slicing and preemption (OS-dependent).
- Multiple threads can run simultaneously on multicore CPUs.

---

## Does `start()` Immediately Execute a Thread?

No.

```
Thread t = new Thread(...);

t.start();

System.out.println("Main");
```

Possible Output

```
Main
Thread
```

or

```
Thread
Main
```

Calling `start()` only makes the thread **RUNNABLE**. Execution begins whenever the scheduler assigns CPU time.

# Frequently Asked Interview Questions

### 1. How many official Java thread states are there?

**Six:** `NEW`, `RUNNABLE`, `BLOCKED`, `WAITING`, `TIMED_WAITING`, and `TERMINATED`.

---

### 2. Why is `RUNNING` not an official Java thread state?

Because Java combines the OS-level **READY** and **RUNNING** states into a single **RUNNABLE** state. The JVM relies on the operating system for scheduling and cannot reliably distinguish whether a runnable thread is merely eligible to run or is actively executing.

---

### 3. What is the difference between `BLOCKED` and `WAITING`?

- **BLOCKED:** Waiting to acquire a `synchronized` monitor lock.
- **WAITING:** Waiting indefinitely for another thread to perform an action such as `notify()`, `notifyAll()`, or completion of a joined thread.

---

### 4. What is the difference between `WAITING` and `TIMED_WAITING`?

- **WAITING:** Waits indefinitely.
- **TIMED_WAITING:** Waits only for a specified duration.

---

### 5. Can a terminated thread be started again?

No. Calling `start()` on a terminated thread throws `IllegalThreadStateException`.

---
6. **explain Thread Lifecycle –**

**Definition:**

> "Thread Lifecycle is the sequence of states a thread passes through from its creation until it completes execution. Java defines these states using the `java.lang.Thread.State` enum. A thread does not execute immediately after creation; it transitions between different states based on method calls, synchronization, and scheduler decisions."

---

## 1. NEW

A thread is in the **NEW** state when its object has been created but the `start()` method has not yet been called.

- Thread object exists.
- No CPU is allocated.
- Not scheduled by the JVM.

**Transition:** `start()` → **RUNNABLE**

---

## 2. RUNNABLE

After calling `start()`, the thread enters the **RUNNABLE** state.

A RUNNABLE thread:

- Is eligible to run.
- May be waiting for CPU time.
- May already be executing on the CPU.

**Important Interview Point:**  
Java **does not have a separate RUNNING state**. It combines the operating system's **READY** and **RUNNING** states into a single **RUNNABLE** state.

---

## 3. BLOCKED

A thread enters the **BLOCKED** state when it is waiting to acquire a monitor lock (`synchronized`) that is currently held by another thread.

Once the lock becomes available, the thread moves back to **RUNNABLE**.

---

## 4. WAITING

A thread enters the **WAITING** state when it waits indefinitely for another thread to perform an action.

Common methods:

- `wait()`
- `join()`
- `LockSupport.park()`

The thread remains in this state until another thread calls `notify()`, `notifyAll()`, or the joined thread finishes.

---

## 5. TIMED_WAITING

A thread enters **TIMED_WAITING** when it waits for a specified amount of time.

Common methods:

- `sleep()`
- `wait(timeout)`
- `join(timeout)`

After the timeout expires, the thread automatically returns to **RUNNABLE**.

---

## 6. TERMINATED

A thread enters the **TERMINATED** state after its `run()` method completes or exits due to an uncaught exception.

A terminated thread **cannot be restarted**. Calling `start()` again throws an `IllegalThreadStateException`.

---

# Interview Summary

> "A Java thread starts in the **NEW** state. When `start()` is called, it moves to **RUNNABLE**, where it is eligible for CPU execution. If it waits for a synchronized lock, it enters **BLOCKED**. If it waits indefinitely for another thread, it enters **WAITING**. If it waits for a specified duration, it enters **TIMED_WAITING**. Finally, after the `run()` method finishes, it reaches the **TERMINATED** state. Java defines six official thread states and does not have a separate **RUNNING** state because it combines the operating system's READY and RUNNING states into the single **RUNNABLE** state."
# Quick Revision Table

|State|Meaning|Common Methods|
|---|---|---|
|NEW|Thread object created|`new Thread()`|
|RUNNABLE|Ready to run or currently running|`start()`|
|BLOCKED|Waiting for a monitor lock|`synchronized`|
|WAITING|Waiting indefinitely|`wait()`, `join()`, `park()`|
|TIMED_WAITING|Waiting for a limited time|`sleep()`, `wait(timeout)`, `join(timeout)`|
|TERMINATED|Execution completed|`run()` finishes|

> **Interview Tip:** If asked to draw the thread lifecycle, always include the six official states and clearly explain that **Java has no separate `RUNNING` state**—this is one of the most commonly tested multithreading concepts.
